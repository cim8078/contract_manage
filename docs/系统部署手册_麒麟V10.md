# 潭合同 台账管理系统 · 麒麟 V10 部署操作指引

版本：V1.2　|　适用系统：银河麒麟 V10（桌面版 / 高级服务器版，x86_64 与 aarch64；含 SP1/SP2/2403 等更新版本）　|　适用程序：“潭合同”台账管理系统　|　编制：系统管理员　|　修订：2026-10-12

> **V1.2 修订说明（2026-10-12）**：部署环境要求**恢复为 Python 3.8+**（V1.1 曾临时要求 3.12+，现撤回）。原因：生产服务器为 **Python 3.8 且无法升级**，因此**代码侧已做双向兼容改造**（`app.py` 中把含 `\uXXXX` 转义的取值移出 f-string 表达式），同一份代码现可在 **Python 3.8 ~ 3.12** 下运行。第 4 章恢复为"Python 3.8+ 环境"（麒麟桌面版自带 3.8 可直接使用；仅低于 3.8 时才需安装）；**新增第十四章「编码约束（Python 3.8 兼容）」**，明确禁止在 f-string 表达式内使用反斜杠与同类引号嵌套，并要求提交前用 3.8 做语法自检；程序包清单（新增 `contract_no.py`）与验收项（Python ≥3.8、SQLite ≥3.25）保留。

> 本指引面向麒麟 V10 服务器的系统管理员，按顺序操作即可完成“潭合同”台账管理系统的部署、开机自启、防火墙放行、数据备份与常见问题排查。全文命令以 `#` 表示需要 root 或 sudo 权限；`$` 表示普通用户即可执行。
>
> 由于麒麟 V10 存在“桌面版（apt 体系）”与“高级服务器版（yum/dnf 体系）”两个分支，第 2 章先教您识别当前系统属于哪一支，请务必先完成识别，再按对应小节操作。

## 一、部署前需要知道的事

### 1.1 系统技术特点

“潭合同”台账管理系统是轻量级 Web 应用，非常适合麒麟 V10 单机或内网部署：

| 项目 | 说明 |
|------|------|
| 后端 | Python **3.8+** / Flask，单文件 `app.py`（另含编号规则模块 `contract_no.py`）；代码兼容 Python 3.8 ~ 3.12 |
| 前端 | `templates/index.html` 单页应用，依赖已全部本地化到 `static/vendor/`，**运行时不依赖外网** |
| 数据库 | SQLite（`data/合同台账.db`），无需单独安装数据库服务 |
| 依赖 | 仅 `flask`、`openpyxl`、`filelock` 三项 |
| 附件 | 存储在 `data/attachments/` 目录 |
| 服务端口 | 默认 `5000`（可在 `app.py` 末尾修改） |

### 1.2 服务器配置建议

| 项目 | 最低要求 | 建议 |
|------|----------|------|
| CPU | 2 核 | 4 核 |
| 内存 | 2 GB | 8 GB |
| 磁盘 | 10 GB | 50 GB（考虑附件与备份增长） |
| Python | **3.8+**（系统自带 3.8 即可） | 3.8.x ~ 3.12（**无需升级**） |
| 浏览器（客户端） | Chrome / Edge / 火狐等现代浏览器 | 麒麟桌面版自带浏览器即可 |

### 1.3 两种部署形态

- **全新部署（空库）**：只传程序文件，不带 `data/合同台账.db`，首次启动自动建库并写入默认管理员；
- **带数据迁移部署**：程序包中包含现有 `data/合同台账.db` 与 `data/attachments/`，部署后直接延续现有台账数据。

下文默认按“全新部署 + 使用现有程序包”讲解，带数据迁移时会单独说明。

## 二、识别麒麟版本并做环境核对

在服务器上用 root 或 sudo 执行：

```
cat /etc/os-release
cat /etc/kylin-release 2>/dev/null
uname -m
python3 --version
command -v apt-get || command -v yum || command -v dnf
```

按输出判断：

| 输出特征 | 属于 | 后文对应章节 |
|----------|------|--------------|
| 出现 `apt` / `apt-get`，版本类似 Ubuntu 20.04 | 麒麟桌面版 V10（含 SP1/SP2/2403 等） | 4.1 节（apt 命令） |
| 出现 `dnf`（`yum` 是其别名） | 银河麒麟高级服务器 V10 SP1+ | 4.2 节（dnf 命令） |
| 只有 `yum` | 银河麒麟服务器 V10 SP0 / 中标麒麟 V7 等 | 4.2 节（yum 命令） |

同时确认：

1. `python3 --version` 必须为 **3.8 及以上**（麒麟 V10 桌面版自带 3.8，满足要求、可直接使用）。若低于 3.8（服务器版常见为 3.6），请按 4.3 节安装较新版本；
2. `uname -m` 输出 `x86_64` 或 `aarch64`，离线下载依赖包时要据此选择；
3. 确认系统已开通 SSH（远程管理用）：`systemctl status sshd`，未开启则执行 `systemctl enable --now sshd`。

## 三、获取并上传程序包

### 3.1 程序包应包含的内容

生产服务器只需以下内容（不含 `.git`、`__pycache__`、`backups/` 等开发文件）：

```
app.py                # 主程序
contract_no.py        # 合同编号规则模块（app.py 直接 import，缺失将无法启动）
requirements.txt
templates/            # 含 index.html
static/               # 含 logo.jpg 与 vendor/ 完整目录
data/                 # 业务数据（全新部署可留空，自动初始化）
docs/                 # 可选，用于存档本手册
```

### 3.2 在 Windows 开发机打包（推荐 tar 方式）

注意：项目内有 `data/合同台账.db`、`data/attachments/` 等**中文文件名/路径**。用 Windows 资源管理器“压缩文件夹”生成的 zip 可能使用 GBK 文件名，解压到 Linux 后中文名乱码，导致程序找不到数据库。**推荐使用 Windows 10/11 自带 tar 命令打包**（UTF-8 文件名兼容好）：

```
cd C:\Users\jghq\Desktop\contract_manager
tar -a -c -f C:\Users\jghq\Desktop\contract_manager_deploy.tar.gz app.py requirements.txt templates static data docs
```

也可以用 WinSCP / scp 直接整目录上传，不打散打包。

### 3.3 上传到麒麟服务器

```
scp C:\Users\jghq\Desktop\contract_manager_deploy.tar.gz root@服务器IP:/tmp/
```

在麒麟服务器上解压到部署目录：

```
sudo mkdir -p /opt/contract_manager
sudo tar -xzf /tmp/contract_manager_deploy.tar.gz -C /opt/contract_manager
ls -l /opt/contract_manager
ls /opt/contract_manager/data/
```

> 务必确认 `data/` 下中文文件名显示正常。若出现 `???` 或乱码，说明打包/解压编码有问题，请改用 3.2 节 tar 方式或 WinSCP 重传。

## 四、安装 Python 环境

> **版本要求：Python 3.8 及以上**。麒麟 V10 桌面版自带 `python3` 通常为 **3.8，满足要求、可直接使用，无需安装**。
> 本项目代码已做**双向兼容改造**，同一份代码在 **Python 3.8 ~ 3.12** 下均可运行。
> **仅当系统自带 `python3` 低于 3.8**（银河麒麟高级服务器版常见为 3.6）时，才需要按 4.3 节安装较新版本。
>
> ⚠️ 开发机若使用更高版本（如 3.12），所写代码必须遵守 **第十四章「编码约束（Python 3.8 兼容）」**，
> 否则会出现"开发机正常、服务器（3.8）起不来"，典型症状为：
> `SyntaxError: f-string expression part cannot include a backslash`（仅 3.12+ 允许 f-string 表达式内出现反斜杠）。

### 4.1 麒麟桌面版（apt 体系）

```
sudo apt-get update
sudo apt-get install -y python3 python3-pip python3-venv
python3 --version
```

Ubuntu 20.04 内核的麒麟 V10 桌面版安装后通常为 Python **3.8**，**满足要求，可直接用于本系统**。

### 4.2 麒麟高级服务器版（yum/dnf 体系）

SP0 / 中标麒麟使用：

```
sudo yum install -y python3 python3-pip python3-devel
python3 --version
```

SP1+ 使用：

```
sudo dnf install -y python3 python3-pip python3-devel
python3 --version
```

如果系统默认 `python3` **低于 3.8**（如 3.6），请执行 4.3 节安装较新版本（3.8+ 即可，推荐 3.10）。

### 4.3 版本不足时源码编译（以 Python 3.10.14 为例）

先安装编译依赖。

apt 体系：

```
sudo apt-get install -y build-essential wget zlib1g-dev libbz2-dev libssl-dev libncurses5-dev libsqlite3-dev libreadline-dev tk-dev libffi-dev
```

yum/dnf 体系：

```
sudo yum groupinstall -y "Development Tools"
sudo yum install -y wget zlib-devel bzip2-devel openssl-devel ncurses-devel sqlite-devel readline-devel tk-devel libffi-devel
```

下载官方源码并编译安装到 `/opt/python310`（**不覆盖系统 Python，最安全**）：

```
cd /usr/local/src
sudo wget https://www.python.org/ftp/python/3.10.14/Python-3.10.14.tgz
sudo tar xzf Python-3.10.14.tgz
cd Python-3.10.14
sudo ./configure --enable-optimizations --prefix=/opt/python310
sudo make -j$(nproc)
sudo make altinstall
/opt/python310/bin/python3 --version          # 应输出 Python 3.10.14
```

> ⚠️ **两条红线**
> 1. 必须装到 `/opt/python310`（或 `/usr/local`）并使用 **`make altinstall`**，**绝不能 `make install` 覆盖 `/usr/bin/python3`** —— 麒麟的 yum/dnf 与系统工具依赖自带 Python，覆盖会导致包管理不可用；
> 2. 编译前**必须**安装 `sqlite-devel`（apt：`libsqlite3-dev`）与 `openssl-devel`（apt：`libssl-dev`），否则 `sqlite3` / `ssl` 模块会缺失；本系统要求 **SQLite ≥ 3.25**（v14 迁移使用 `ALTER TABLE … RENAME COLUMN`）。
> 若服务器完全离线，需在联网机器先下载 Python 源码包及全部编译依赖（或用同架构联网麒麟下载 rpm/deb 离线安装包），再拷入服务器安装。

### 4.4 验证 Python 与虚拟环境组件（必须通过）

```
python3 -c "import sys, sqlite3; print('Python', sys.version.split()[0], '| SQLite', sqlite3.sqlite_version)"
python3 -m venv /tmp/venv_test && rm -rf /tmp/venv_test
```

- 要求：**Python ≥ 3.8 且 SQLite ≥ 3.25.0**；
- 若 `python3 -m venv` 报 `ensurepip is not available` 或找不到 venv 模块：apt 体系补装 `python3-venv`；yum/dnf 体系安装 `python3-virtualenv` 后改用 `virtualenv`；
- 若使用了 4.3 节编译的 Python，请把上面的 `python3` 换成 `/opt/python310/bin/python3`。

> 说明：本系统**只要求 Python 3.8+**，不需要安装 3.12。若操作系统已自带 3.8（麒麟 V10 桌面版即是），本章可跳过，直接进入第五章。

## 五、创建专用运行账号并赋权

为了安全和便于管理，建议用独立系统账号运行服务：

```
sudo useradd -r -s /usr/sbin/nologin contract 2>/dev/null || echo "账号已存在"
sudo chown -R contract:contract /opt/contract_manager
```

> 若计划先以当前用户做前台启动测试，可先跳过本节，测试完成后再建账号并执行 `sudo chown -R contract:contract /opt/contract_manager`。

## 六、创建虚拟环境并安装依赖

### 6.1 创建虚拟环境

**用系统自带的 `python3`（3.8，满足要求）创建虚拟环境**：

```
cd /opt/contract_manager
sudo -u contract python3 -m venv venv
./venv/bin/python -V            # 应显示 Python 3.8.x（或更高，本项目兼容 3.8~3.12）
```

> 若系统自带 `python3` 低于 3.8（已按 4.3 节安装了新版本），则改用该解释器：`sudo -u contract /opt/python310/bin/python3 -m venv venv`。

### 6.2 在线安装依赖（服务器可访问互联网或内网 PyPI 镜像）

```
cd /opt/contract_manager
sudo -u contract ./venv/bin/pip install --upgrade pip
sudo -u contract ./venv/bin/pip install -r requirements.txt
./venv/bin/pip list
```

公网访问受限但允许访问国内镜像时，可先配置清华源再安装：

```
sudo -u contract ./venv/bin/pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
sudo -u contract ./venv/bin/pip install -r requirements.txt
```

### 6.3 离线安装依赖（服务器无外网）

第一步：在一台**可联网且与服务器同架构（x86_64 或 aarch64）、同 Linux 大版本、同 Python 版本（3.8）**的机器上执行：

```
mkdir -p /tmp/wheels
python3 -m pip download -r requirements.txt -d /tmp/wheels
```

> 请务必用**与服务器相同版本**的 Python 下载，否则轮子（如 `cp38` 与 `cp312`）不匹配、无法安装。

第二步：把 `/tmp/wheels` 整个目录拷贝到麒麟服务器（如 `/opt/contract_manager/pkg/`），然后离线安装：

```
cd /opt/contract_manager
sudo -u contract ./venv/bin/pip install --no-index --find-links=/opt/contract_manager/pkg -r requirements.txt
```

> 依赖中 `MarkupSafe`（Flask 的间接依赖）含 C 扩展加速包，**不能拿 Windows 上 `pip download` 的轮子到麒麟安装**。请务必用 Linux 同架构机器下载，或用 6.2 节在线安装。
>
> 实在只有联网 Windows 机器时，可尝试指定平台参数下载 manylinux 轮子（示例：x86_64 + Python 3.8 执行 `python -m pip download -r requirements.txt -d pkg --platform manylinux2014_x86_64 --python-version 3.8 --implementation cp --abi cp38 --only-binary=:all:`；aarch64 将平台换成 `manylinux2014_aarch64`，**Python 版本务必与服务器一致**）。此方式兼容性风险较高，建议优先使用同架构 Linux 下载。

### 6.4 无 venv 时的直接安装方式（备用）

若服务器缺少虚拟环境组件且无法补装，可省略 venv，直接用系统 Python 安装，后续 systemd 的 `ExecStart` 同步改为 `python3`：

```
cd /opt/contract_manager
sudo pip3 install -r requirements.txt
```

> 前提：系统 `python3` 已满足 **≥3.8**（用 `python3 --version` 确认）；若低于 3.8，请改用 4.3 节安装的解释器（如 `/opt/python310/bin/pip3`）。

## 七、首次启动与数据初始化

### 7.1 前台启动测试

先以可写权限前台运行，观察初始化输出（全新部署会自动建库、建目录、写默认数据）：

```
cd /opt/contract_manager
./venv/bin/python app.py
```

正常输出应类似：

```
[INFO] 潭合同 台账管理系统 启动中...
[INFO] 数据库: /opt/contract_manager/data/合同台账.db
[INFO] 访问地址: http://localhost:5000
[INFO] 默认管理员: admin / 123456
 * Running on http://0.0.0.0:5000
```

另开一个终端验证：

```
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:5000/
ss -lntp | grep 5000
```

预期分别返回 `200` 并显示 5000 端口监听。若 `data/` 原本为空，此时已生成 `data/合同台账.db` 与 `backups/`。

验证后按 `Ctrl+C` 停止前台进程。

> 无图形界面的服务器在启动时会尝试打开浏览器，可能打印无害的错误提示，不影响服务运行。正式部署请直接使用第 8 章 systemd 方式启动。

### 7.2 带现有数据迁移时的核对

如果程序包已带 `data/合同台账.db` 与 `data/attachments/`，启动前请先核对：

```
ls -l /opt/contract_manager/data/
```

确认数据库文件、Excel、附件目录都在；**不要**删除 `合同台账.db`。首次启动不会执行 Excel 迁移，直接使用现有数据库。

> **结构迁移（2026-09-29 版，`schema_version` v1~v18）**：启动时会自动、幂等地补齐数据库结构迁移，日志中会出现若干 `[MIGRATE] schema_version <版本>: <说明>` 行（v12 新增资产租金收缴表、v13 删除资产合同旧租金列、v14 列改名、v15 删除合同级缴款方式、v16/v17 收缴表缴款方式枚举化与默认值、v18 统计索引），二次启动不再输出。升级前请注意：
> 1. 先做一次数据库备份（`sqlite3 "…/合同台账.db" ".backup '…/合同台账_$(date +\%Y\%m\%d).db'"`，或整目录打包）；
> 2. v13/v15/v17 会**重建表**（关闭外键→重建→外键校验→提交），请确认升级期间无人正在使用系统，并保证磁盘余量；
> 3. v14 使用 `ALTER TABLE … RENAME COLUMN`，要求 **SQLite ≥ 3.25**（用 4.4 节命令实测 `sqlite3.sqlite_version`；若自行编译的 Python 未装 `sqlite-devel`，其 sqlite3 模块可能缺失或版本偏低，需补装后重新编译；系统自带 Python 则需先升级系统 SQLite）；
> 4. 迁移完成后可用 `sqlite3 "…/合同台账.db" "SELECT MAX(version) FROM schema_version;"` 核对是否已到 18。
> 另：如需为每个资产合同初始化租金收取记录，可执行随包提供的 `_seed_asset_rent_collections.sql`（幂等，可按需重复执行）。

## 八、注册为 systemd 系统服务（开机自启）

### 8.1 创建服务文件

```
sudo tee /etc/systemd/system/contract-manager.service > /dev/null <<'EOF'
[Unit]
Description=潭合同 台账管理系统 (Kylin V10)
After=network.target

[Service]
Type=simple
User=contract
Group=contract
WorkingDirectory=/opt/contract_manager
Environment=LANG=C.UTF-8
Environment=PYTHONIOENCODING=utf-8
ExecStart=/opt/contract_manager/venv/bin/python /opt/contract_manager/app.py
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
EOF
```

说明：

- 若 6.4 节未使用 venv，将 `ExecStart` 改为 `/usr/bin/python3 /opt/contract_manager/app.py`（可用 `command -v python3` 确认路径；**需确认该 python3 ≥ 3.8**）；
- 使用 6.1 节创建的 venv 时保持默认的 `/opt/contract_manager/venv/bin/python /opt/contract_manager/app.py` 即可（venv 解释器来自系统 `python3` 或 4.3 节安装的解释器）；
- 如需换端口（例如 8080），编辑 `app.py` 末尾 `app.run(host="0.0.0.0",port=5000,...)` 中的 `5000`，并同步调整防火墙放行端口；
- 麒麟启用了 KYSEC/SELinux 等安全模块且服务启动异常时，先注释掉 `NoNewPrivileges` 等加固项排查（上例未启用加固项，天然兼容性最好），或参考第 12 章。

### 8.2 启动并设置开机自启

```
sudo chown -R contract:contract /opt/contract_manager
sudo systemctl daemon-reload
sudo systemctl enable contract-manager
sudo systemctl start contract-manager
sudo systemctl status contract-manager
```

看到 `active (running)` 即成功。

### 8.3 查看日志

```
sudo journalctl -u contract-manager -n 100 --no-pager
sudo journalctl -u contract-manager -f
```

## 九、防火墙放行与内网访问

### 9.1 firewalld（高级服务器版常用）

```
sudo systemctl status firewalld
sudo firewall-cmd --permanent --add-port=5000/tcp
sudo firewall-cmd --reload
sudo firewall-cmd --list-ports
```

如使用了 Nginx 且只走 80/443，可只放行 `http`/`https` 服务：

```
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --permanent --add-service=https
sudo firewall-cmd --reload
```

## 十、可选：Nginx 反向代理与 HTTPS

生产环境建议将 5000 端口收敛到内网，由 Nginx 对外提供 80/443。安装：

apt 体系：

```
sudo apt-get install -y nginx
```

yum/dnf 体系：

```
sudo yum install -y nginx
```

新建 `/etc/nginx/conf.d/contract_manager.conf`：

```
server {
    listen 80;
    server_name contract.example.local;   # 换成实际主机名或 IP
    client_max_body_size 25m;             # 附件上传上限需大于系统设置中的上限

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 300s;
    }
}
```

启用：

```
sudo nginx -t
sudo systemctl enable --now nginx
sudo systemctl reload nginx
```

HTTPS 证书就绪后，将 `listen 80` 改为 `listen 443 ssl;` 并加入 `ssl_certificate`、`ssl_certificate_key` 两行，或将 80 端口配置为跳转 443。系统已兼容反向代理，日志记录的客户端 IP 会自动读取 `X-Forwarded-For`。

### 11.1 需要备份的数据

| 路径 | 内容 | 重要程度 |

| `/opt/contract_manager/data/合同台账.db` | 全部业务数据 | 核心，必须备份 |

系统本身在每次写操作前会自动把数据库备份到 `backups/`（保留 30 天），但应另做每周异地备份。

### 11.2 手动整目录备份

```
sudo mkdir -p /backup/ht
sudo tar -czf /backup/ht/ht_full_$(date +%Y%m%d).tar.gz -C /opt/contract_manager data
```

### 11.3 SQLite 在线备份

先确认 `sqlite3` 命令存在；没有则按体系安装（`apt-get install -y sqlite3` 或 `yum install -y sqlite`）：

```
sudo mkdir -p /backup/ht
sudo sqlite3 "/opt/contract_manager/data/合同台账.db" ".backup '/backup/ht/合同台账_$(date +%Y%m%d).db'"
```

### 11.4 定时自动备份（crontab）

编辑 root 的 crontab：

```
sudo crontab -e
```

加入以下两行（每周六 2:00 全量打包、每周六 2:30 SQLite 在线备份；注意 crontab 中 `%` 必须写成 `\%`）：

```
0 2 * * 6 mkdir -p /backup/ht && tar -czf /backup/ht/ht_full_$(date +\%Y\%m\%d).tar.gz -C /opt/contract_manager data
30 2 * * 6 mkdir -p /backup/ht && sqlite3 "/opt/contract_manager/data/合同台账.db" ".backup '/backup/ht/合同台账_$(date +\%Y\%m\%d).db'"
```

建议备份目录放在独立磁盘/存储，并每月将备份拷到异地。

### 11.5 数据恢复

整体恢复步骤：

```
sudo systemctl stop contract-manager
sudo cp /backup/ht/ht_full_YYYYMMDD.tar.gz /tmp/
cd /tmp
sudo tar -xzf ht_full_YYYYMMDD.tar.gz
sudo cp -r data /opt/contract_manager/
sudo chown -R contract:contract /opt/contract_manager/data
sudo systemctl start contract-manager
```

恢复后登录验证：合同总数与备份时一致、附件可下载、操作日志可查询。

## 十四、开发与维护编码约束（Python 3.8 兼容）

> 本章面向**后续开发与维护人员**。生产服务器为 **Python 3.8**，而开发机可能使用更高版本（如 3.12）。
> **高版本能跑低版本语法，反之不行**——因此所有代码必须遵守本章约束，保证"开发机写的代码在麒麟服务器 3.8 上也能跑"。

### 14.1 为什么需要本章（一次真实事故的教训）

`app.py` 中曾有两处写法仅 **Python 3.12+** 合法：

```python
# ✗ 事故代码（仅 Python 3.12+ 可用）
return [f"{d['\u5355\u4f4d\u540d\u79f0']}-{d['\u79d1\u5ba4\u540d\u79f0']}" for d in get_all_depts()]
```

该写法在 **3.11 及更早版本**上会在**编译源码阶段**报错（不是运行时异常）：

```
SyntaxError: f-string expression part cannot include a backslash
```

表现为：**开发机（3.12）一切正常，部署到麒麟服务器（3.8）后 `import app` 直接失败、服务起不来**。
现该处已按 14.3 的写法改正，并在原位置保留了注释说明。

### 14.2 硬性禁止清单

| 禁止 | 说明 |
|---|---|
| ❌ 在 **f-string 表达式内**出现**反斜杠** | 含 `\uXXXX`、`\n`、`\t`、`\"` 等（Python 3.12/PEP 701 才放宽）。本项目中文列名以 `\uXXXX` 转义书写，**最容易踩这一条** |
| ❌ 在 **f-string 表达式内**嵌套**同类引号** | 如 `f"{d["键"]}"`（内外层同为双引号），3.12 才允许；外层双引号时内层必须用单引号 |
| ❌ 使用 **3.9+** 特性 | `str.removeprefix/removesuffix`、`dict1 \| dict2` 字典合并、`list[str]` 等内建泛型注解、`functools.cache`、`zoneinfo`、`graphlib`、`tomllib` |
| ❌ 使用 **3.10+ / 3.11+** 特性 | `match/case`、`X \| Y` 联合类型注解、`typing.Self`、`ExceptionGroup`/`except*` |
| ✅ 允许 | 海象运算符 `:=`（3.8+）、f-string 基本用法、`typing.List[str]` 等 `typing` 泛型 |

> 注：`#` **注释里**写 `\uXXXX` 没问题（注释不参与转义解析）；但**字符串/文档字符串里**若要表达字面的 `\uXXXX`，必须写成 `\\uXXXX`（双反斜杠），否则会报 `SyntaxError: (unicode error) 'unicodeescape' ... truncated \uXXXX escape`。

### 14.3 正确写法（推荐范式）

**把含转义的取值放到 f-string 外面**，f-string 内只引用变量：

```python
# ✓ 允许：取值在 f-string 之外，f-string 内只有变量（兼容 Python 3.8 ~ 3.12）
def _dept_display(d):
    """返回部门的显示名「单位名称-科室名称」。"""
    unit = d["\u5355\u4f4d\u540d\u79f0"]      # 单位名称
    room = d["\u79d1\u5ba4\u540d\u79f0"]      # 科室名称
    return f"{unit}-{room}"                   # 表达式内无反斜杠、无同类引号嵌套
```

等效替代写法（同样兼容 3.8）：`"{}-{}".format(d["单位名称"], d["科室名称"])` 或字符串直接相加。

### 14.4 提交前自检（强烈建议纳入日常）

在麒麟服务器或任意 Python 3.8 环境上执行：

```bash
python3 -m py_compile app.py contract_no.py      # 退出码 0 即通过
python3 -m compileall -q .                       # 更彻底
```

只要该命令通过，代码即可在服务器上导入运行；**开发仍可在更高版本（如 3.12）进行**，只是不能使用 3.12 专有语法。
