# 数据库完整性规范化修改内容（A-01 ~ A-08 汇总）

> 说明：按对话执行顺序汇总本项目（`contract_manager`，数据库 `data/合同台账.db`，SQLite）8 次数据库结构与记录的修改。
> 每项先说明**修改目的**，再以清单列出**修改内容**（数据库结构修改 / 数据库记录修改 / 备份与回滚 / 解决的问题）。
> 与各次对话生成的专项文档一致：`docs/A-01`~`docs/A-08` 系列（见附录二）。

---

## 一、A-01 建立数据库级唯一索引（contracts.编号）

**修改目的**
- 为合同台账表 `contracts` 的“编号”列添加数据库级唯一约束，使编号唯一性在数据库层兜底——即使绕过 API 直接写入，数据库层也能拒绝重复编号（改动前仅靠应用层接口校验）。

**修改内容清单**
1. 数据库结构修改（1 项）：
   - 新增唯一索引：`CREATE UNIQUE INDEX IF NOT EXISTS idx_contracts_no ON contracts("编号")`；
   - 迁移前先扫描存量重复编号（`GROUP BY "编号" HAVING c>1`），存在重复则终止并输出清单，禁止静默删除。
2. 数据库记录修改：0 条（实测 639 条合同“编号”全部非空且无重复）。
3. 备份/回滚：回滚语句 `DROP INDEX IF EXISTS idx_contracts_no`，不影响数据。
4. 解决的问题：任何写入路径出现已存在编号都会触发 `UNIQUE constraint failed`；为后续 A-03 外键（附件→合同编号）提供唯一引用目标。

## 二、A-02 重建 departments 表为复合主键表

**修改目的**
- 为 `departments` 表添加复合主键（单位名称, 科室名称），杜绝重复部门组合，使组合唯一性在数据库层兜底（改动前无主键、无唯一约束）。

**修改内容清单**
1. 数据库结构修改（1 项）：
   - 重建 `departments` 表：`"单位名称" TEXT NOT NULL, "科室名称" TEXT NOT NULL, PRIMARY KEY ("单位名称","科室名称")`；
   - SQLite 无法 `ALTER TABLE` 加主键，采用“建新表→拷贝→DROP→RENAME”流程，`BEGIN…COMMIT` 事务包裹，迁移前先校验存量无重复组合。
2. 数据库记录修改：0 条（13 行原样拷入新表，内容不变）。
3. 备份/回滚：原表 DDL 与 13 行 INSERT 写入 `data/departments_ddl_backup.sql`，供回滚。
4. 解决的问题：插入重复组合或 NULL 科室名会被数据库拒绝；为 A-03 外键（contracts/users 的 所属单位/所属科室 → departments）提供“唯一、非空”的引用目标。

## 三、A-03 外键约束与部门数据修复

**修改目的**
- 为系统添加外键约束（`attachments.合同编号→contracts.编号`、`users.所属部门→departments`、`contracts.所属部门→departments`），并全局开启 SQLite 外键开关，数据库层保证引用完整性（改动前均为“字符串外键”，删除部门/用户可能产生悬空引用）。

**修改内容清单**
1. 数据库结构修改（3 项 + 触发器）：
   - 重建 `contracts`/`users`/`attachments` 三张表并声明外键（`ON DELETE RESTRICT ON UPDATE CASCADE`）；
   - `_conn()` 每个连接执行 `PRAGMA foreign_keys=ON`；
   - 新增同步触发器：`trg_contracts_dept_sync_i/u`、`trg_users_dept_sync_i/u`（所属部门字符串 ↔ 所属单位/所属科室外键列自动同步）、`trg_departments_rename_sync`（部门改名级联同步）。
2. 数据库记录修改（71 条）：
   - 修复“所属部门缺科室后缀”数据：71 条“湘潭市机关事务管理局后勤中心”按项目名称关键字规则（R1 公车/车辆、R2 周转房、R3 工程建设、R4 物业管理、R5 市民之家、R6 兜底）追加科室后缀，如“湘潭市机关事务管理局后勤中心-物业管理组”；
   - 修复前全量校验 contracts/users/attachments 任一悬空引用即终止；完整对应关系（编号→项目名称→原值→修复值→命中关键字）写入 `docs/A-03-部门数据修复清单.md`。
3. 备份/回滚：重建前/后整库备份（`backups/合同台账_A03_重建前_*.db`、`重建后_*.db`）。
4. 解决的问题：删除被合同/用户/附件引用的部门会被数据库拒绝（RESTRICT），附件、用户、合同的引用完整性由数据库层兜底。

## 四、A-04 常用查询列建索引（contracts）

**修改目的**
- 为 `contracts` 表常用查询列建立索引，提升未来 SQL 化查询与数据量增长后的性能（改动前为全量内存查询，索引不影响现有功能）。

**修改内容清单**
1. 数据库结构修改（新增 5 个普通索引，均幂等 `IF NOT EXISTS`）：
   - `idx_contracts_department`（所属部门）、`idx_contracts_procurement_date`（采购时间）、`idx_contracts_next_bid_date`（下次招采时间）、`idx_contracts_archived`（是否归档）、`idx_contracts_handler`（经办人，过渡索引）；
   - 命名规范 `idx_contracts_<英文>`，避免中文列名入索引名；A-01 的 `idx_contracts_no` 唯一索引直接复用，不重复创建。
2. 数据库记录修改：0 条。
3. 备份/回滚：逐个 `DROP INDEX` 即可，无数据影响。
4. 解决的问题：常用查询/统计/提醒/待支付按部门、时间、归档、经办人过滤的性能基础。

## 五、A-05 CHECK 与 NOT NULL 约束（contracts 重建）

**修改目的**
- 为 `contracts` 表增加 CHECK 约束（金额非负、日期格式、枚举白名单）与 NOT NULL 约束（必填字段），数据库层拒绝非法数据（改动前无任何 CHECK/NOT NULL，非法金额、空必填、非标准枚举均可入库）。

**修改内容清单**
1. 数据库结构修改（重建 `contracts` 表）：
   - 金额 CHECK：合同金额（万元）/结算金额/已支付/未支付/决策的招标控制价 `IS NULL OR CAST(字段 AS REAL) >= 0`；
   - 日期格式 CHECK：采购时间/开工/完工/竣工验收/下次招采时间 `GLOB 'YYYY-MM-DD'`（空值放行）；
   - NOT NULL：编号、项目分类、项目名称、采购方式、合同金额（万元）、资金来源、合同主要内容、经办人、所属部门（与前端必填星号一致）；
   - 枚举 CHECK（项目分类/采购方式/是否结算/资金来源/是否归档）**延后至 A-08 清洗完成后启用**，本次未启用。
2. 数据库记录修改（自动回填 697 条，依据明确规则，非猜测）：
   - 资金来源为空→“其他”635 条；日期格式非 YYYY-MM-DD→正则提取/清空 45 条（完工 16、竣工验收 16、开工 10、采购 3）；合同主要内容空→“待补充”7 条；合同金额空→0 5 条；经办人为空→取兄弟合同或“待补充”3 条；项目名称空→“待补充”1 条；采购方式空→“自行采购”1 条；
   - 金额列非数字文本 245 条**仅列出建议值，未自动修改**（分布：决策的招标控制价 63、已支付 58、未支付 45、合同金额 43、结算金额 36），清单见 `docs/A-05-数据修复清单.md`。
3. 备份/回滚：重建前整库备份（`backups/合同台账_A05_重建前_*.db`）。
4. 解决的问题：负金额、空必填、非标准日期入库被数据库拒绝；金额文本不猜测转换，避免误判（如“潭财办发[2014]15号”→2014 并非金额）。

## 六、A-06 修正不规范字段类型

**修改目的**
- 修正不规范字段类型：`attachments.文件大小` TEXT→INTEGER；日期列统一为 YYYY-MM-DD；数值列（合同金额等）存量文本转为 REAL。

**修改内容清单**
1. 数据库结构修改（1 项）：
   - 重建 `attachments` 表，`文件大小` 列类型由 TEXT 改为 INTEGER（实测当前 `PRAGMA table_info(attachments)`：`文件大小:INTEGER`）。
2. 数据库记录修改：
   - 日期列：A-05 已统一处理，本项复扫 5 个日期列自动规范化 0 条、无法解析 0 条（实测当前各日期列非合规数均为 0）；无法解析的日期绝不静默置空，清单见 `docs/A-06-日期规范化清单.md`；
   - 金额列：245 条存量文本值（与 A-05 第二节一致）**不做猜测转换**，逐条导出“建议值”供业务确认后回填，清单见 `docs/A-06-金额类型转换确认清单.md`。
3. 备份/回滚：恢复迁移前备份；或重建旧结构并回填原值。
4. 解决的问题：附件文件大小以整数存储；日期格式统一可被 `parse_date()` 正常解析；金额列类型与展示/统计口径一致。

## 七、A-07 版本化迁移机制（schema_version）

**修改目的**
- 建立数据库结构版本化迁移机制：新增 `schema_version` 表，将 `init_db()` 中散落的 ad-hoc `ALTER TABLE` 迁移改写为按版本号顺序执行且幂等的迁移脚本列表，使结构变更可追溯、可重复执行。

**修改内容清单**
1. 数据库结构修改（新增 1 张表 + 3 个迁移）：
   - 新增 `schema_version` 表（`version`/`applied_at`/`description`，实测当前 3 行：v1/v2/v3）；
   - v1：contracts 追加历史字段列（资金来源/是否归档/归档人/归档时间）；
   - v2：contracts 列改名（经办人/分管领导→经办人、甲方现场负责人→现场负责人）；
   - v3：users 追加 分管部门 字段；
   - 执行机制：仅执行 `version > 当前最大版本`，每个迁移独立事务、失败回滚不记录版本、启动自动补迁、`[MIGRATE]` 日志；新增结构变更只追加新版本号，禁止修改历史版本。
2. 数据库记录修改：0 条（v1~v3 在已升级库上为幂等空操作；旧库升级实测补列/改名成功且数据保留）。
3. 附带修复：全新库首次启动 `_seed_defaults()` 外键报错（A-03 触发器回填外键列、先插用户后插部门导致），调整为先插部门再插用户。
4. 备份/回滚：删除版本行可强制重跑对应版本；整体回滚依赖重启前备份（`backups/合同台账_版本迁移重启前_20260823_202631.db`）。

**修改内容清单**
1. 数据库结构修改：无（仅数据清洗）。
2. 数据库记录修改（共 531 条次）：
   - 项目分类 113 条：工程类 56→建设项目、维修类 26+维修维护类 22→维护维修类、委托支付函 6+造价咨询服务 1+补充协议 2（按主合同）→服务类；

   - 是否结算 11 条：按季度/按月/按年度结算→是（结算金额=已支付>0、未支付=0 判定）、按月支付/由具体实施的单项项目结算→否（建议值）、`/`→空；原值追加到备注保留审计痕迹；“部分结算”1 条保留（建议新增标准值，待业务确认）；
   - 所属部门：0 条（A-03 已修复原 71 条，复扫全部可匹配 departments 组合）。
3. 备份/回滚：清洗前备份 `backups/合同台账_A08_清洗前_20260823_204107.db`；清洗脚本 `_migrate_a08.py` 留存（幂等，重跑自动退出）。
4. 解决的问题：清洗后项目分类/采购方式全部为标准值，是否结算仅剩 是/否/空/部分结算，后续启用 A-05 枚举 CHECK 不会因存量非标准值失败；金额/支付字段逐条差异 0，总数 639 不变，仅枚举标签标准化。
