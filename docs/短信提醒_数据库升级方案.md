# 合同台账系统 —— 短信提醒功能「数据库完善与升级方案」（草案，未执行）

> 目标：按“最小化、够用”的原型思路，为**合同到期提醒 / 待收提醒 / 待支提醒**增加短信通道，
> 支持「每周一 09:00 自动提醒」+「项目合同下单独短信催办」+「点对点发送」，并保留发送留痕与回执/回复。
> 本文只涉及**数据库层**（表结构 + 配置 + 版本化迁移）；不含接口/前端开发。

---

## 一、结论先行

1. **不新增业务主表**：到期/待收/待支提醒已由现有表推导，短信功能是“只读现有数据 + 写发送流水”，
   因此只需 **2 张新表**（模板、发送流水）+ **若干 settings 配置项** + 两主表各 1 列「短信提醒」开关。
2. **接入现有迁移框架**：在 `app.py` 的 `MIGRATIONS` 列表尾部追加 `v20~v23`，全部幂等、无需 `own_transaction`，
   不触碰任何历史版本、不改动现有表结构（仅 v23 追加开关列）。
3. **“未办结/未归档/未永久关闭”全部可推导**，不需要为每个提醒单独建状态表（映射见第三节）。

---

## 二、可直接复用的现状（无需改造）

| 需求要素 | 现有实现 | 位置 |
|---|---|---|
| 经办人手机号 | `users.姓名 → users.电话`（v19 已加「电话」列） | `users` 表 |
| 经办人姓名（多值） | `project_contracts."经办人"`，可能形如 `刘勇/刘聚丰`，已有多值拆分函数 `_split_names()` | `project_contracts` |
| 现场负责人手机号 | `project_contracts."现场负责人"`（v2 已列）→ `users.姓名 → users.电话` | `project_contracts` / `users` |
| 承租人手机号 | `asset_contracts."承租人" + "联系电话"`（直取，无需匹配用户） | `asset_contracts` |
| 责任人手机号 | `asset_contracts."责任人"` → `users.姓名 → users.电话` | `asset_contracts` / `users` |
| 到期提醒口径 | `下次招采时间 − 提醒提前天数`（项目）/ `下次出租时间 − 提醒提前天数`（资产） | `_reminders` / `_asset_reminders` |
| 待支提醒口径 | 未归档 且 `待支付金额 > 0`（`_pending_unpaid`） | `api_pending_payments` |
| 待收提醒口径 | `asset_rent_collections` 按合同分组 `SUM(应缴)−SUM(实缴) > 0` | `asset_rent_collections` |
| 归档 / 永久关闭 | `是否归档='是'`；永久关闭 = 清空「下次招采时间 / 下次出租时间」（`clear_remind`） | 两主表 |
| 配置读写 | `settings` 键值表 + `get_cfg/set_cfg` + `/api/config` | `settings` |

结论：短信功能是**叠加层**，数据库侧改动面极小。

## 三、提醒“开/停”判定口径（数据库可推导，不落冗余状态）

| 提醒类型 | 继续提醒（未办结） | 停止提醒（办结/归档/永久关闭） |
|---|---|---|
| 合同到期提醒 | 「下次招采时间 / 下次出租时间」非空 且 已进入提前期 | 该日期为空（永久关闭）或 已归档 |
| 待支提醒 | `是否归档≠是` 且 待支付>0 | 已归档 或 已支付 ≥ 合同金额 |
| 待收提醒 | 未归档 且 应收差额>0 | 已归档 或 实缴 ≥ 应缴 |
| 通用开关（已启用） | — | 合同「短信提醒」列 = '关闭' |

> 说明：「永久关闭」沿用现有 `clear_remind`（清空日期）语义，前端文案已叫“永久关闭提醒”，口径统一。

### 收件人解析规则（按提醒场景 × 合同类型）

| 场景 | 项目合同（project_contracts） | 资产合同（asset_contracts） |
|---|---|---|
| 合同到期提醒 | **经办人**、**现场负责人** | **责任人**、**承租人** |
| 待支提醒 | **经办人** | —（无此场景） |
| 待收提醒 | —（无此场景） | **责任人**、**承租人** |
| 催办 / 点对点 | 操作人指定（默认带出该合同经办人） | 操作人指定 |

号码来源与匹配规则：

- **经办人 / 现场负责人 / 责任人**：按姓名到 `users.姓名` **精确匹配**，取 `users.电话`；
  姓名支持多值（顿号、斜杠、分号分隔，复用 `_split_names()`），逐个解析、**按手机号去重**。
- **承租人**：直接取 `asset_contracts."联系电话"`（无需匹配用户）。
- 解析落空（姓名匹配不到用户 / 用户无电话 / 承租人无联系电话）→ **不发送**，
  在 `sms_logs` 记一条“无号码”失败记录，便于补录后重发。
- **每人一条**：同一提醒对同一手机号只发一条，去重键含手机号（见第五节）。

> 数据现状提醒：现网 29 个用户中仅 1 个填了「电话」；且存在姓名形近差异
> （如资产责任人 `曾明峰` 与用户 `曾明锋`、`杨宏玮` 与 `杨宏伟`）。
> 上线前需先补录电话并核对姓名，否则收件人解析会大量落空（仅留痕不报错）。

> 说明：「永久关闭」沿用现有 `clear_remind`（清空日期）语义，前端文案已叫“永久关闭提醒”，口径统一。

| `sms_secret_key` | `1621c79cb951475986621ad4baec2fdf` | 平台 SK（签名用，勿外泄） |
| `sms_weekly_enabled` | `1` | 每周自动提醒开关 |

### v21 — sms_templates（短信模板）

```sql
CREATE TABLE IF NOT EXISTS sms_templates (
  "场景"     TEXT PRIMARY KEY,          -- expire/receivable/payable/urge/manual
  "场景名称" TEXT NOT NULL,
  "模板内容" TEXT NOT NULL,              -- 支持占位符 {name}{number}{due}{days}{tenant}{amount}{note}
  "启用"     TEXT DEFAULT '是',
  "更新时间" TEXT, "更新人" TEXT
);
```

默认模板（占位符在发送时替换；实际下发内容前自动拼接签名）：

- `expire` 到期提醒：`合同「{name}」（编号{number}）将于{due}到期，剩余{days}天，请及时办理。`
- `receivable` 待收提醒：`资产合同「{name}」（承租方{tenant}）尚有租金{amount}元未收讫，请及时处理。`
- `payable` 待支提醒：`项目合同「{name}」（编号{number}）尚有未支付金额{amount}万元，请及时办理支付。`
- `urge` 催办：`合同「{name}」（编号{number}）提醒事项请尽快办理：{note}`
- `manual` 点对点：`{content}`

### v22 — sms_logs（短信发送流水，核心表）

```sql
CREATE TABLE IF NOT EXISTS sms_logs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  "时间"       TEXT,      -- 发送时间 yyyy-mm-dd HH:MM:SS
  "场景"       TEXT,      -- 到期/待收/待支/催办/点对点
  "关联类型"   TEXT,      -- 项目合同/资产合同
  "关联ID"     TEXT,      -- project_contracts.id 或 asset_contracts.id
  "关联编号"   TEXT,      -- 合同编号（项目）/资产名称编号
  "关联名称"   TEXT,
  "接收人类型" TEXT,      -- 经办人/承租人/手动
  "接收人"     TEXT,      -- 姓名/单位
  "手机号"     TEXT,
  "短信内容"   TEXT,      -- 含签名，实际下发内容
  "去重键"     TEXT,      -- 见第五节；同一提醒同一周同一号码仅一条
  "触发方式"   TEXT,      -- 定时/催办/点对点
  "发送人"     TEXT,      -- 定时=系统；催办/点对点为操作人用户名
  "状态"       TEXT,      -- 待发送/成功/失败
  "外部guId"   TEXT,      -- 平台返回的消息 id（回执/回复对账用）
  "回执状态码" TEXT, "回执描述" TEXT,      -- 回执回调写入
  "回复时间"   TEXT, "回复内容" TEXT,      -- 回复回调写入（就近覆盖最近一条）
  "错误信息"   TEXT,                       -- 失败原因/平台返回原文
  "请求时间戳" INTEGER                     -- 发往平台的 timestamp（签名用）
);
CREATE INDEX IF NOT EXISTS idx_sms_logs_time     ON sms_logs("时间");
CREATE INDEX IF NOT EXISTS idx_sms_logs_object   ON sms_logs("关联类型","关联ID");
CREATE INDEX IF NOT EXISTS idx_sms_logs_phone    ON sms_logs("手机号");
CREATE INDEX IF NOT EXISTS idx_sms_logs_status   ON sms_logs("状态");
CREATE INDEX IF NOT EXISTS idx_sms_logs_guid     ON sms_logs("外部guId");
CREATE UNIQUE INDEX IF NOT EXISTS idx_sms_logs_dedup
  ON sms_logs("去重键") WHERE "去重键" IS NOT NULL AND "去重键" <> '';
```

### v23 — 两主表增加短信开关列（**已确认启用**）

支持“单条合同不想收短信但保留提醒”的场景，空值视为开启，向后兼容：

```sql
ALTER TABLE project_contracts ADD COLUMN "短信提醒" TEXT;   -- 开启/关闭，空=开启
ALTER TABLE asset_contracts   ADD COLUMN "短信提醒" TEXT;
```

> 关闭后该合同不再参与任何自动/催办短信（点对点手动发送仍允许）；空值与 `开启` 等价，向后兼容。
> 停发条件 = 「短信提醒=关闭」 或 已归档 或 已办结（见第三节）。

## 五、去重与定时口径（数据库侧保障）

- **去重键格式**：`{场景}|{关联类型}|{关联ID}|{手机号}|{ISO年-周}`，例如
  `expire|project|123|13800000000|2026-W41`。
- **每周一次**：定时任务按周生成去重键 → 命中 `idx_sms_logs_dedup` 唯一索引则跳过，天然防重发；
  即使服务重启/重复触发，同一周同一提醒+同一号码也只发一条。
- **每人一条**：去重键含手机号，同一提醒的多个收件人（多经办人、责任人+承租人）各发各的、互不覆盖。
- **防重复触发**：`settings.sms_last_run_at` 记录上次执行时间，配合上面唯一索引形成“双保险”。
- 手动**催办 / 点对点**：不带周去重键（`去重键` 留空），按次发送、全部留痕。

```python
MIGRATIONS += [
    (20, "settings 追加短信平台配置项（AK/SK、开关、每周提醒时间等）", _mig_v20_sms_settings),
```

约束与约定（沿用现有规范）：
- 每个迁移函数**保持幂等**（存在即跳过；列存在性用 `PRAGMA table_info` 判断）。
- **不修改历史版本**；新变更只追加新版本号。
- v20~v23 均为**纯新增**（建表/加列/加配置），不重建被外键引用的表，**无需 `own_transaction`**。
- 配置默认值用 `INSERT OR IGNORE`，避免覆盖用户已改过的线上值（仅首次写入）。

## 七、部署前提与风险（务必先确认）

1. **网络可达**：官方文档要求先开通 `10.129.17.93:443`、`sms.xtdzzw.cn:443` 网络策略，
   服务端需在**政务网内**方能访问（互联网不通）。上线前用 `telnet` 验证。
2. **账号合规**：文档 1.2 明确“应用系统用户账号须由统一身份认证平台同步，不得自行新建无关账号”，
   手机号来源需符合该要求。
3. **AK/SK 保密**：当前方案将 SK 存入 `settings`（明文）。原型可用；若正式上线建议改用环境变量或加密存储，
   并限制 `/api/config` 仅管理员可读、日志不回显 SK。
4. **数据缺口（最大阻塞）**：现网 29 个用户中**仅 1 个填了「电话」**。
   必须先把经办人 / 现场负责人 / 责任人的电话补录到 `users.电话`，否则收件人解析会大量落空
   （仅写“失败/无号码”流水，不报错）；同时需核对姓名形近差异（`曾明峰`/`曾明锋`、`杨宏玮`/`杨宏伟`）。
5. **承租人范围（已确认）**：`承租人/联系电话` 仅资产（租赁）合同存在，指中标/实际实施单位联系人；
   项目合同不发送给承租人，只有经办人 + 现场负责人。
6. **签名与模板**：平台要求应用自定义签名并审核，**签名由平台按应用签名自动添加**；系统写入的正文**不得包含「【】」**（会被判多签名而阻断），故本系统默认不在正文拼接签名（见《政务短信平台使用注意事项》）。

## 八、已确认口径（本次定稿）

1. **项目合同**收件人 = 经办人；电话取 `users.电话`，按姓名精确匹配。
2. **资产合同**收件人 = 承租人 + 责任人；承租人电话取 `asset_contracts.联系电话`，
   责任人电话取 `users.电话`（承租人 = 中标/实际实施单位联系人）。
3. **到期提醒**额外发给**现场负责人**，电话取 `users.电话`。
4. 每周提醒**每人一条**（去重键含手机号）。
5. **启用** v23 单合同「短信提醒」开关列。
6. 发送时段**可在设置页调整**：`sms_weekly_weekday / hour / minute`（默认周一 09:00）；另提供总开关 `sms_enabled`、周提醒开关 `sms_weekly_enabled`。

## 附录：已实现（v20–v23 + 发送服务）

数据库迁移 v20–v23 已执行，`schema_version = 23`；发送服务、定时任务、回执接口与前端已开发完成。

**发送机制**：统一走 `/message/smsBatch`（点对点批量，一号码一内容一 guId，`guId = SMS{流水id}` 便于回执对账）；
签名 = 参数 ascii 升序 `k=v&…` + `key=SK`，MD5 大写，`sign` 与 `sendData` 不参与。

**新增接口**

| 方法/路径 | 说明 | 权限 |
|---|---|---|
| `GET /api/sms/status` | 短信状态（开关/时间/签名/上次执行） | 登录 |
| `POST /api/sms/run_weekly` | 立即执行本周提醒（等于定时任务，force） | 管理员 |
| `GET /api/sms_recipients?kind=&scene=&id=` | 预览合同默认收件人 | 登录+写范围 |
| `POST /api/contracts/<cid>/sms_urge` | 项目合同短信催办 | 非查询用户+写范围 |
| `POST /api/contracts/<cid>/sms` | 项目合同点对点发送 | 同上 |
| `POST /api/asset_contracts/<aid>/sms_urge` | 资产合同短信催办 | 同上 |
| `POST /api/asset_contracts/<aid>/sms` | 资产合同点对点发送 | 同上 |
| `POST /api/sms/send` | 独立点对点发送（无合同上下文，供“短信发送记录”页使用） | 非查询用户 |
| `POST /api/sms/resend` | 失败记录重发（按 `sms_logs.id`，仅“失败”且本人触发；原记录保留，另写 `触发方式=重发` 流水） | 非查询用户 |
| `PUT /api/contracts/<cid>/sms_switch` · `PUT /api/asset_contracts/<aid>/sms_switch` | 单合同「短信提醒」开/关 | 同上 |
| `GET /api/sms_logs` | 发送记录（管理员全部，其他仅本人） | 登录 |
| `GET /api/sms_templates` · `PUT /api/sms_templates/<scene>` | 模板查看 / 修改 | 登录 / 管理员 |
| `POST /api/sms/callback/receipt` · `POST /api/sms/callback/reply` | 回执/回复回调（免登录，可按 `sms_receipt_token` 校验） | 平台 |
| `GET/PUT /api/config` | 追加 `sms` 配置（GET 掩码 SK；PUT 掩码值不覆盖） | 登录 / 管理员 |
| `POST /api/sms/test_connection` | 平台连通性测试（DNS + TCP，不发短信），返回分步结果与中文提示 | 管理员 |

**可配置超时**：`settings.sms_timeout_sec`（默认 10 秒，1–120），用于连接/读取超时；政务内网较慢时可调大。
**错误提示**：底层网络异常（超时/域名解析失败/连接被拒/TLS 失败/HTTP 错误）统一翻译为中文可操作提示，
并把原文附在括号内；失败记录一并写入 `sms_logs."错误信息"`。

**定时任务**：后台守护线程每 30s 检查一次；命中 `sms_weekly_weekday(1=周一)/hour/minute` 且当天未执行时触发一次
（`settings.sms_last_run_at` 占位防重），周末/工作日均可配置；每周每人一条由 `sms_logs."去重键"` 唯一索引保证。

**前端**：系统设置内新增「短信提醒设置」「短信模板」两卡；侧栏新增「短信记录」页；
项目/资产合同编辑弹窗新增「短信提醒」按钮（含单合同开关、模板催办、点对点发送、收件人预览）。
