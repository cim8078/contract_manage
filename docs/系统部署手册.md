## 一、系统概述

### 1.1 系统简介

“潭合同”台账管理系统是湘潭市机关事务管理局内部使用的合同台账管理软件，用于合同信息的新增、修改、删除、查询、统计、导出，以及重新采购到期提醒。系统为轻量级 Web 应用，后端使用 Python Flask，前端为单页面 HTML（Vue.js 3 + Bootstrap 5，已本地化无外网依赖），数据存储使用 SQLite 数据库（兼容从 Excel 台账一键迁移）。

### 1.2 技术架构

| 层次 | 技术 | 说明 |
|------|------|------|
| 前端 | HTML + CSS + JavaScript（Vue 3 / Bootstrap 5 / Chart.js / SheetJS / Bootstrap Icons） | 单文件 `templates/index.html`，依赖已本地化至 `static/vendor/`，无需外网 |
| 后端 | Python 3.8+ / Flask | `app.py` 提供全部 REST API |
| 数据存储 | SQLite（`data/合同台账.db`） | 7 张业务表（合同、用户、部门、配置、附件、操作日志、schema_version 版本记录） |
| Excel 兼容 | openpyxl | 台账模板下载、Excel 导出、首次启动数据迁移 |
| 并发控制 | 线程锁 + SQLite | 写操作串行化，保证数据一致 |
| 备份机制 | 自动备份 | 每次写操作前自动备份数据库至 `backups/`，保留 30 天 |

### 1.3 系统组成文件

| 路径 | 类型 | 说明 |
|------|------|------|
| `app.py` | 程序文件 | Flask 主程序（约 129KB），全部后端逻辑 |
| `requirements.txt` | 依赖清单 | flask、openpyxl、filelock |
| `templates/index.html` | 前端页面 | 完整单页应用，含全部 CSS/JS |
| `static/logo.jpg` | 配置文件 | 单位 LOGO（登录页 80×80、顶栏 32×32） |
| `static/vendor/` | 静态资源 | 本地化的前端依赖库 |
| `data/合同台账.db` | 数据文件 | SQLite 主数据库（核心数据，需重点保护） |
| `data/合同台账.xlsx` | 数据文件 | Excel 台账工作簿（首次启动自动迁移用；下载模板/导出） |
| `data/attachments/` | 数据目录 | 合同附件文件（PDF、图片等） |
| `data/departments_ddl_backup.sql` | 脚本文件 | departments 重建前备份脚本（A-02 治理步骤备份） |
| `backups/` | 备份目录 | 自动备份的数据库文件（保留 30 天） |

| `docs/` | 文档目录 | 部署手册、操作手册、评审建议、提升实施方案、开发文档、A-01~A-08 治理文档、数据库完整性规范化修改内容及 docx 版本 |

## 三、全新部署步骤

### 3.1 准备程序包

将项目目录整体拷贝至服务器，例如 `C:\contract_manager`（Windows）或 `/opt/contract_manager`（Linux）。程序包至少包含：

```
app.py
requirements.txt
templates/index.html
static/logo.jpg
static/vendor/（完整目录）
data/（可空，首次启动自动创建）
```

> 若程序包内已含 `data/合同台账.db`，则为带数据部署（迁移/升级场景），请直接执行 3.3 之后步骤并先备份原数据。

### 3.2 安装 Python 与依赖

**Windows：**

1. 到 Python 官网（https://www.python.org/downloads/）下载并安装 Python 3.8+，安装时勾选“Add Python to PATH”；
2. 打开命令提示符（CMD），进入项目目录：
```
cd C:\contract_manager
python --version
pip install -r requirements.txt
```
3. 可选：使用虚拟环境隔离依赖：
```
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

**Linux：**

```
cd /opt/contract_manager
python3 --version
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

> 依赖清单仅三项：`flask`、`openpyxl`、`filelock`。如服务器无外网，可离线安装（在联网机器上 `pip download -r requirements.txt -d ./pkg`，再拷贝到服务器 `pip install --no-index --find-links=./pkg -r requirements.txt`）。

### 3.3 配置单位 LOGO

- 将单位 LOGO 图片重命名为 `logo.jpg`，放入 `static/` 目录（覆盖默认文件）；
- 推荐尺寸：正方形 300×300 以上，文件小于 2 MB；
- LOGO 缺失不影响系统运行，界面将显示 80×80 虚线占位框；部署完成后请人工检查登录页与顶栏 LOGO 是否正常显示。

### 3.4 首次启动与数据初始化

在项目目录执行：

**Windows：**
```
python app.py
```

**Linux：**
```
python3 app.py
```

启动过程系统会自动完成：

| 步骤 | 说明 |
|------|------|
| 创建目录 | 自动创建 `data/`、`backups/`、`static/`、`data/attachments/` 等目录 |
| 初始化数据库 | 创建 `data/合同台账.db` 及六张业务表 |
| Excel 迁移 | 若 `data/合同台账.xlsx` 存在且数据库为首次创建，自动将 Excel 五个工作表（合同台账、用户表、部门列表、系统配置、合同附件）迁移至 SQLite |
| 写入默认数据 | 默认管理员 `admin / 123456`、默认部门“湘潭市机关事务管理局本级-办公室”、默认配置（提醒 60 天、日志保留 90 天） |
| 打开浏览器 | 自动打开 `http://localhost:5000` |

启动成功的标准输出：

```
[INFO] 潭合同 台账管理系统 启动中...
[INFO] 数据库: C:\contract_manager\data\合同台账.db
[INFO] 访问地址: http://localhost:5000
[INFO] 默认管理员: admin / 123456
```

### 3.5 部署验证

1. 服务器本机浏览器访问 `http://localhost:5000`，应显示登录页（蓝色渐变背景、LOGO、系统名称）；
2. 使用 `admin / 123456` 登录；
3. 登录后首页应显示五张统计卡片（总合同数、总合同额、已/将到期合同数、待支付项目数、待支付总金额），并显示“合同到期提醒”与“待支付提醒”两个列表区域；
4. 检查“合同台账”页可正常加载列表，“日志审计”页可查询操作日志；
5. 检查登录页与顶栏 LOGO 正常显示。

### 3.6 开放防火墙端口（内网访问必需）

**Windows Server：** 以管理员身份运行命令提示符：

```
netsh advfirewall firewall add rule name="潭合同台账-5000" dir=in action=allow protocol=TCP localport=5000
```

**Linux（firewalld）：**

```
firewall-cmd --permanent --add-port=5000/tcp
firewall-cmd --reload
```

**Linux（ufw）：**

```
ufw allow 5000/tcp
```

然后使用局域网内另一台电脑访问 `http://服务器IP:5000` 验证。

### 3.7 设置开机自启

**Windows（任务计划程序）：**

1. 打开“任务计划程序”→ 创建任务；
2. 常规：名称“潭合同台账管理系统”，勾选“不管用户是否登录都要运行”；
3. 触发器：选择“计算机启动时”；
4. 操作：启动程序，程序为 Python 安装路径（如 `C:\Python310\python.exe`），参数 `app.py`，起始于 `C:\contract_manager`。

**Linux（systemd 服务）：** 创建 `/etc/systemd/system/contract-manager.service`：

```
[Unit]
Description=潭合同台账管理系统
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/contract_manager
ExecStart=/opt/contract_manager/venv/bin/python /opt/contract_manager/app.py
Restart=always
RestartSec=5
User=www-data

[Install]
WantedBy=multi-user.target
```

启用并启动：

```
systemctl daemon-reload
systemctl enable contract-manager
systemctl start contract-manager
systemctl status contract-manager
```

## 四、数据与备份管理

### 4.1 数据文件说明

| 文件/目录 | 内容 | 备份要求 |
|-----------|------|----------|
| `data/合同台账.db` | 全部业务数据（合同、用户、部门、配置、附件索引、操作日志、schema_version 版本记录） | 核心数据，必须备份 |
| `data/attachments/` | 合同附件文件（决策依据、合同、验收结算附件） | 与数据库一同备份 |
| `data/合同台账.xlsx` | Excel 工作簿（模板来源、首次迁移数据源） | 数据导入源，建议保留 |
| `data/departments_ddl_backup.sql` | departments 重建前备份脚本（A-02 治理步骤备份） | 随数据一同备份 |
| `backups/` | 系统自动备份的数据库文件（含 A 系列治理快照，见 4.7 节） | 由系统自动管理，保留 30 天 |

### 4.2 自动备份机制

- 系统在**每次写操作**（新增、修改、删除、归档、导入、用户/部门管理、配置修改等）执行前，自动将 `data/合同台账.db` 完整备份为 `backups/合同台账_YYYYMMDD_HHMMSS.db`；
- 备份文件保留 **30 天**，超期自动清理（仅清理 `backups/` 下扩展名为 `.db` 的文件）；
- 备份机制保障任何一次写操作前都有可回滚快照。

### 4.3 手动备份方法

**方法一：直接拷贝（推荐定期执行）**

1. 停止服务（或确认无人在线操作）；
2. 将 `data/` 整个目录拷贝至异地存储（U盘、文件服务器、云盘）：
```
copy /y C:\contract_manager\data C:\backup\data_20260818
```
3. 建议每周备份一次，每月异地归档一次。

**方法二：在线备份（无需停服）**

使用 SQLite 在线备份命令（Linux）：
```
sqlite3 /opt/contract_manager/data/合同台账.db ".backup '/backup/合同台账_20260818.db'"
```

### 4.4 数据恢复方法

**场景一：单条数据误删/误改** —— 从最新备份中取回记录：

1. 定位最近的备份文件（`backups/` 中时间戳最新的 `.db`）；
2. 使用 SQLite 工具（或联系开发人员）从备份中导出该条记录；
3. 将记录写回当前数据库。

**场景二：数据库损坏/丢失，需整体恢复：**

1. 停止服务；
2. 将备份文件拷贝为 `data/合同台账.db`（覆盖损坏文件）；
3. 同时恢复 `data/attachments/` 目录（如有对应备份）；
4. 启动服务并登录验证数据完整性。

### 4.5 从 Excel 台账迁移数据

- 若旧版系统仅保留 Excel 台账，将 Excel 文件放置为 `data/合同台账.xlsx`（要求包含“合同台账、用户表、部门列表、系统配置、合同附件”五个工作表，列名与系统一致），**删除或移走 `data/合同台账.db`** 后首次启动，系统自动完成迁移；
- 迁移完成后请核对合同总数、用户数、部门数，并在“日志审计”中确认无异常。

### 4.6 备份恢复操作规程

**备份频率与保留：**

| 备份类型 | 频率 | 保留 | 执行方式 |
|----------|------|------|----------|
| 自动备份 | 每次写操作前 | 30 天 | 系统自动，无需人工干预 |
| 手动全量备份 | 每周一次 | 至少 3 份滚动 | 拷贝 `data/` 目录（4.3 方法一） |
| 异地归档 | 每月一次 | 长期 | 拷贝备份至异地存储（文件服务器/云盘） |
| 恢复演练 | 每季度一次 | 记录归档 | 按下方演练步骤执行 |

**恢复演练步骤：**

1. 在演练机（或备用目录）创建独立目录，拷贝最近一次备份的 `.db` 文件与 `attachments/` 附件目录；
2. 停止正式服务后（或在演练机独立启动），将备份文件复制为 `data/合同台账.db`，恢复 `data/attachments/`；
3. 启动服务，验证：管理员登录、合同总数与备份时一致、抽查附件可下载、日志可查询；
4. 演练完成后在《系统功能提升实施方案》6.3 节恢复演练记录表中登记：演练日期、演练人、演练方式、恢复数据量、结果、备注。

**注意事项：**

- 恢复前务必备份当前损坏/异常数据，避免覆盖丢失；
- 数据库与附件必须成对恢复，附件缺失会导致下载失败；
- 恢复后立即修改一次默认密码并核对关键配置（提醒天数、日志保留天数）。

### 4.7 数据库治理快照回滚

2026-08 完成的数据库完整性规范化治理（A-01~A-08）期间，`backups/` 保留了各治理步骤的快照文件，可用于回滚对应治理步骤：

- 命名规则：`backups/合同台账_A0x_*.db`（A0x 对应治理步骤编号，如 A-03、A-05、A-06、A-08）；
- 现有快照包括：A-03 重建前/后、A-05 重建前、A-06 附件重建前/后、版本迁移重启前、A-08 清洗前等；
- `data/departments_ddl_backup.sql` 为 departments 重建前备份脚本（A-02）。

回滚方法（同 4.4 场景二）：

1. 停止服务；
2. 将对应治理步骤的快照文件拷贝为 `data/合同台账.db`（如涉及附件，同时恢复 `data/attachments/`）；
3. 启动服务并验证数据完整性（管理员登录、合同总数、附件下载、日志查询）。

> 治理快照随自动备份保留 30 天，需长期保留请另行归档；恢复后再执行升级，请核对 `schema_version` 迁移状态（见 5.3 节）。

## 五、系统升级

### 5.1 升级前准备

1. 完整备份 `data/` 目录（数据库 + 附件）；
2. 记录当前版本号与已启用的功能配置（系统设置中的提醒天数、日志保留天数）；
3. 检查目标版本更新说明，确认数据兼容性。

### 5.2 升级步骤

1. 停止服务：
   - Windows：结束 `python app.py` 进程；
   - Linux：`systemctl stop contract-manager`；
2. 备份后，使用新版本文件覆盖：`app.py`、`templates/index.html`、`requirements.txt`、`static/`（如有变更）；
3. **不要覆盖** `data/` 与 `backups/` 目录；
4. 更新依赖：`pip install -r requirements.txt`；
5. 启动服务，程序会自动执行数据库结构升级（建表/加列/字段更名等，幂等安全）；
6. 用管理员登录，验证合同列表、统计、提醒、日志各功能正常。

**升级后检查表：**

| 检查项 | 方法 |
|--------|------|
| 合同总数不变 | 首页五张统计卡片对比升级前记录 |
| 首页提醒正常 | 合同到期提醒、待支付提醒列表可正常加载与展开/折叠 |
| 用户/部门不变 | 用户管理页核对 |
| 附件可下载 | 抽查 2～3 个附件下载 |
| 统计口径正常 | 查询统计页执行一次统计 |
| 日志正常记录 | 执行一次操作后到日志审计查看 |
| 备份正常生成 | 触发一次写操作，确认 `backups/` 新增文件 |

### 5.3 版本升级说明

| 版本 | 说明 |
|------|------|
| V1.0 | 初始版本（当前运行版） |
| V1.1（计划） | 合同状态字段、财务勾稽校验、敏感操作留痕等，详见《系统功能提升实施方案》 |
| V1.2（计划） | 密码加固、登录防护、会话密钥环境变量、提醒主动触达等 |
| V1.3（计划） | 统计增强、编号规则化、批量操作、导入增强等 |

**数据库自动迁移（schema_version）：**

- 升级时直接覆盖程序文件（`app.py` 等）并重启即可，无需手工执行建表/加列 SQL；
- `app.py` 启动时 `init_db()` 自动调用 `_run_versioned_migrations()`，按版本号依次执行未应用的迁移（MIGRATIONS v1~v3），迁移事务包裹，失败自动回滚；
- 迁移日志以 `[MIGRATE]` 前缀写入 `app.log.err`，可据此确认迁移执行结果；
- 后续新增结构变更由开发向 MIGRATIONS 追加版本号，部署包内不再需要单独 SQL 脚本；
- 如需强制重跑某版本：停止服务后删除 `schema_version` 表中对应版本行，再启动（迁移幂等，可安全重跑）；
- 结构回滚依赖治理快照备份（见 4.7 节），请勿手工修改 `schema_version` 版本号。

| `templates/index.html` | 前端（如版本相同） |
| `app.py`、`requirements.txt` | 后端程序 |
| `static/` | LOGO 与本地化前端资源 |

### 6.2 迁移步骤

1. 在旧服务器停止服务并做最终备份；
2. 将 `data/`、`templates/`、`static/`、`app.py`、`requirements.txt` 拷贝至新服务器；
3. 新服务器按第 3 章 3.2/3.3 安装环境与依赖（**保留 `data/合同台账.db`，不要删除**，跳过 Excel 迁移）；
4. 启动并验证：合同总数、用户数、部门数、附件数与旧服务器一致；
5. 修改网络配置（防火墙、DNS、反向代理）后切换用户访问。

> 迁移后请立即验证管理员登录、合同列表、统计图表、提醒、附件下载、日志查询六大功能。

### 7.3 常见问题排查

| 现象 | 可能原因 | 处理方法 |
|------|----------|----------|
| 访问 `http://localhost:5000` 无响应 | 服务未启动 / 端口被占用 | 查看启动输出；`netstat -ano \| findstr :5000` 检查端口占用 |
| 报错 `ModuleNotFoundError: No module named 'flask'` | 依赖未安装 | 执行 `pip install -r requirements.txt` |
| 局域网其他电脑无法访问 | 防火墙未放行 / 监听地址错误 | 执行 3.6 防火墙命令；确认 `app.py` 中 `host="0.0.0.0"` |
| 登录页 LOGO 不显示（占位框） | `static/logo.jpg` 缺失或文件名错误 | 确认文件名、大小写与路径 |
| 页面显示中文乱码 | 文件编码被改动 | 用 UTF-8 保存 `app.py`、`templates/index.html` |
| 数据未显示最新 | 浏览器缓存 | Ctrl+F5 强制刷新 |
| 忘记管理员密码 | 密码遗忘 | 按 7.4 重置密码 |
| 端口 5000 被其他程序占用 | 端口冲突 | 修改 `app.py` 末尾 `port=5000` 为其他端口，并同步放行防火墙 |
| 附件下载 404 | 附件文件被移动/清理 | 按 4.4 场景二从备份整体恢复 `attachments/` |
| 升级后数据库自动迁移失败 | 迁移执行异常（`app.log.err` 中无 `[MIGRATE]` 完成记录） | 检查 `app.log.err` 中 `[MIGRATE]`/`[ERROR]` 日志定位原因；必要时从治理快照恢复数据库（见 4.7 节）后联系开发 |

### 7.4 重置管理员密码

**当前版本（V1.0）**：停止服务后，在服务器上执行以下 Python 脚本（将“新密码”替换为实际密码）：

```
import hashlib, sqlite3
SALT = "xtsgj_2024_contract"
pw = hashlib.sha256(("新密码" + SALT).encode()).hexdigest()
con = sqlite3.connect(r"C:\contract_manager\data\合同台账.db")
con.execute('UPDATE users SET "密码"=? WHERE "用户名"=?', (pw, "admin"))
con.commit(); con.close()
print("密码已重置")
```

重新启动服务后用新密码登录。

> 说明：升级至 V1.1（计划）后，密码将改用 PBKDF2 哈希存储，重置脚本同步更新（见《系统功能提升实施方案》3.1 节）。升级前请保留本版脚本。

## 八、安全加固建议

| 项目 | 建议 | 优先级 |
|------|------|--------|
| 默认口令 | 首次登录后立即修改 `admin` 密码（在“用户管理”中重置或修改个人信息） | 高 |
| 会话密钥 | 设置环境变量 `SECRET_KEY` 为随机长字符串（见 8.2 节） | 高 |
| HTTPS | 生产环境建议通过 Nginx/Caddy 反向代理启用 HTTPS，禁止明文传输 | 高 |
| 访问控制 | 仅在可信内网开放；如跨网段，配置防火墙来源 IP 白名单 | 中 |
| 账号管理 | 按“最小权限”分配用户角色；离职人员及时禁用/删除账号 | 中 |
| 数据备份 | 每周备份 + 每月异地归档；每季度恢复演练（见 4.6 节） | 高 |
| 审计 | 管理员定期导出操作日志归档（默认保留 90 天，可在系统设置调整） | 中 |
| 系统更新 | 定期更新 Python、Flask 及依赖到安全版本 | 中 |

### 8.1 Nginx 反向代理示例（HTTPS）

```
server {
    listen 443 ssl;
    server_name contract.example.gov.cn;
    ssl_certificate     /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 300s;
        client_max_body_size 50m;
    }
}
```

> 系统已兼容反向代理：日志记录的客户端 IP 优先读取 `X-Forwarded-For` 头。配置完成后请重启 Nginx 并验证。

### 8.2 会话密钥 SECRET_KEY 配置

当前版本（V1.0）会话密钥为源码内置值。安全加固建议（当前即可执行）：

1. 用随机方式生成 64 位十六进制密钥：`python -c "import secrets; print(secrets.token_hex(32))"`；
2. 将 `app.py` 中 `app.secret_key = "xtsgj_contract_manager_secret_key_2026"` 替换为生成的随机值；
3. 重启服务生效；修改密钥会使所有已登录会话失效，请选择低峰期执行并通知用户重新登录。

> V1.1（计划）将支持环境变量 `SECRET_KEY` 配置（无需改源码），见《系统功能提升实施方案》3.3 节。

### 8.3 登录防护说明

- 当前版本（V1.0）无登录失败次数限制；
- 计划版本（V1.2）将实现“连续失败 5 次锁定 15 分钟”，锁定期间拒绝登录并写入日志；
- 在此之前，请通过防火墙来源 IP 白名单、HTTPS 与强口令策略降低暴力破解风险。

### 8.4 密码存储加固说明

- 当前版本（V1.0）密码采用 SHA256 + 固定盐存储；
- 计划版本（V1.2）将升级为 PBKDF2（werkzeug），历史密码首次登录时自动迁移，无需人工处理；
- 升级后本手册 7.4 节重置脚本将同步更新。
