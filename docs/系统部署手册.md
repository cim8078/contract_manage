## 一、系统概述

### 1.1 系统简介

“潭合同”台账管理系统是湘潭市机关事务管理局内部使用的合同台账管理软件，用于合同信息的新增、修改、删除、查询、统计、导出，以及重新采购到期提醒。系统为轻量级 Web 应用，后端使用 Python Flask，前端为单页面 HTML（Vue.js 3 + Bootstrap 5，已本地化无外网依赖），数据存储使用 SQLite 数据库（兼容从 Excel 台账一键迁移）。

### 1.2 技术架构

| 层次 | 技术 | 说明 |
|------|------|------|
| 前端 | HTML + CSS + JavaScript（Vue 3 / Bootstrap 5 / Chart.js / SheetJS / Bootstrap Icons） | 单文件 `templates/index.html`，依赖已本地化至 `static/vendor/`，无需外网 |
| 后端 | Python **3.8+** / Flask | `app.py` 提供全部 REST API（另含编号规则模块 `contract_no.py`）；**代码兼容 Python 3.8 ~ 3.12** |
| 数据存储 | SQLite（`data/合同台账.db`） | 9 张业务表（项目合同、资产合同、用户、部门、配置、项目合同附件、资产合同附件、操作日志、字段级变更日志）+ schema_version 版本记录 |
| Excel 兼容 | openpyxl | 台账模板下载、Excel 导出、首次启动数据迁移 |
| 并发控制 | 线程锁 + SQLite | 写操作串行化，保证数据一致 |
| 备份机制 | 自动备份 | 每次写操作前自动备份数据库至 `backups/`，保留 30 天 |

### 1.3 系统组成文件

| 路径 | 类型 | 说明 |
|------|------|------|
| `app.py` | 程序文件 | Flask 主程序（约 318KB），全部后端逻辑与版本化迁移 |
| `contract_no.py` | 程序文件 | **合同编号规则模块**（`app.py` 直接 `import`，缺失将无法启动） |
| `requirements.txt` | 依赖清单 | flask、openpyxl、filelock |
| `templates/index.html` | 前端页面 | 完整单页应用，含全部 CSS/JS |
| `tools/browser_smoke.mjs` | 测试脚本 | **前端逐视图冒烟脚本**（发版必跑，见 5.4 节；依赖 Node.js 与 `playwright-core`） |
| `static/logo.jpg` | 配置文件 | 单位 LOGO（登录页 80×80、顶栏 32×32） |
| `static/vendor/` | 静态资源 | 本地化的前端依赖库 |
| `data/合同台账.db` | 数据文件 | SQLite 主数据库（核心数据，需重点保护） |
| `data/合同台账.xlsx` | — | **已停用**（v1.5 起删除，不再依赖 Excel 初始化；增量数据请用系统内置“导入”功能） |
| `data/attachments/` | 数据目录 | 附件文件（项目合同与资产合同附件，PDF、图片等） |
| `backups/` | 备份目录 | 自动备份的数据库文件（保留 30 天） |
| `.git/` | 版本库 | 建议随程序包一并保留（回退与历史追溯依赖它） |
| `app.log` | 日志文件 | 运行日志（启动输出、错误信息） |
| `docs/数据字典表.md` | 文档 | 字段、枚举、主数据标准定义 |
| `docs/` | 文档目录 | 部署手册（含麒麟 V10 版）、用户操作手册、系统开发文档、数据字典表、A-06/A-07 治理文档、第三方许可清单、测试报告（`test_reports/`）及 docx 版本 |

## 二、部署环境要求

### 2.1 服务器要求

| 项目 | 最低要求 | 建议配置 |
|------|----------|----------|
| 操作系统 | Windows Server 2016+ 或 Linux（CentOS 7+/Ubuntu 18.04+/麒麟等） | Windows Server 2019 或 Ubuntu 20.04+ |
| CPU | 2 核 | 4 核 |
| 内存 | 2 GB | 8 GB |
| 磁盘 | 10 GB | 50 GB 以上（含数据增长与备份） |
| 软件 | Python **3.8+**（需能运行 pip） | Python 3.8.x / 3.10+（**兼容 3.8 ~ 3.12，不必升级**） |
| 浏览器 | Chrome / Edge 等现代浏览器 | 客户端无需安装任何软件，仅浏览器访问 |

### 2.2 网络要求

- 系统监听 `0.0.0.0:5000`，默认 HTTP 端口 5000；
- 内网用户通过 `http://服务器IP:5000` 访问；
- 如需公网或跨区域访问，建议部署 HTTPS 反向代理（见第 8 章）。
- **短信功能出网要求（V1.5 新增）**：如需使用“短信提醒”，服务器需能访问湘潭市政务短信服务平台。该平台仅在政务网内可达，须由平台方开通网络策略并报备调用方出网 IP：`sms.xtdzzw.cn:443`、`10.129.17.93:443`。验证命令：`telnet sms.xtdzzw.cn 443`、`telnet 10.129.17.93 443`（两条均能连通即为正常）；也可在“系统设置 → 短信提醒设置”中点击“连接测试”自检。未开通时系统仍可正常使用，仅短信发送失败并在“短信记录”中留痕。

### 2.3 端口规划

| 端口 | 用途 | 说明 |
|------|------|------|
| 5000 | 系统 Web 服务 | 默认端口，如冲突可在 `app.py` 末尾 `app.run(host="0.0.0.0", port=5000, ...)` 修改 |
| 443（出方向） | 短信平台调用 | 仅在使用短信功能时需要；目标地址 `sms.xtdzzw.cn`、`10.129.17.93`，需开通出网策略与 IP 白名单 |

## 三、全新部署步骤

### 3.1 准备程序包

将项目目录整体拷贝至服务器，例如 `C:\contract_manager`（Windows）或 `/opt/contract_manager`（Linux）。程序包至少包含：

```
app.py
requirements.txt
templates/index.html
static/logo.jpg
static/vendor/（完整目录）
data/（可空，首次启动自动创建）
```

> 若程序包内已含 `data/合同台账.db`，则为带数据部署（迁移/升级场景），请直接执行 3.3 之后步骤并先备份原数据。

### 3.2 安装 Python 与依赖

> **版本要求：Python 3.8 及以上即可**（系统自带的 3.8 可直接使用，**无需升级**；3.9/3.10/3.11/3.12 也都能运行）。
> 本项目代码已做**双向兼容改造**（`app.py` 中不再出现"f-string 表达式内含反斜杠"的 3.12 专有写法），因此同一份代码在 **Python 3.8 ~ 3.12** 下均可运行。
> 开发与维护时请遵守 **第九章「编码约束（Python 3.8 兼容）」**，否则可能重蹈"开发机（3.12）正常、服务器（3.8）起不来"的问题。

**Windows：**

1. 到 Python 官网（https://www.python.org/downloads/）下载并安装 **Python 3.8+**（现有 3.8/3.10 环境均可直接使用），安装时勾选“Add Python to PATH”；
2. 打开命令提示符（CMD），进入项目目录并确认版本：
```
cd C:\contract_manager
python --version                    # 应 ≥ 3.8
```
3. 使用虚拟环境隔离依赖（推荐）：
```
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
venv\Scripts\python -c "import sys,sqlite3;print(sys.version.split()[0], sqlite3.sqlite_version)"
```

**Linux / 麒麟：**

```
cd /opt/contract_manager
python3 --version                   # 应 ≥ 3.8（麒麟桌面版通常为 3.8，可直接使用）
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

> 仅当系统自带 `python3` **低于 3.8**（如服务器版常见的 3.6）时，才需要另行安装较新版本；安装方式（apt / yum-dnf / 源码编译）与编译注意事项详见《系统部署手册_麒麟V10》**第 4 章**。
```

> ⚠️ **仅在"系统自带 python3 低于 3.8、需要自行编译"时才涉及的两条红线**（本系统要求 3.8+ 即可，通常无需编译）：① 编译安装一律用 `make altinstall`，**绝不能覆盖 `/usr/bin/python3`**（麒麟的 yum/dnf 依赖它）；② 编译前必须装 `sqlite3-devel`（apt：`libsqlite3-dev`）与 `openssl-devel`，否则 `sqlite3` / `ssl` 模块会缺失，而本系统要求 **SQLite ≥ 3.25**（v14 迁移使用 `ALTER TABLE … RENAME COLUMN`）。

> 依赖清单仅三项：`flask`、`openpyxl`、`filelock`。如服务器无外网，可离线安装（在**同架构、同 Python 版本**的联网机器上 `pip download -r requirements.txt -d ./pkg`，再拷贝到服务器 `pip install --no-index --find-links=./pkg -r requirements.txt`）。

### 3.3 配置单位 LOGO

- 将单位 LOGO 图片重命名为 `logo.jpg`，放入 `static/` 目录（覆盖默认文件）；
- 推荐尺寸：正方形 300×300 以上，文件小于 2 MB；
- LOGO 缺失不影响系统运行，界面将显示 80×80 虚线占位框；部署完成后请人工检查登录页与顶栏 LOGO 是否正常显示。

### 3.4 首次启动与数据初始化

在项目目录执行：

**Windows：**
```
python app.py
```

**Linux：**
```
python3 app.py
```

启动过程系统会自动完成：

| 步骤 | 说明 |
|------|------|
| 创建目录 | 自动创建 `data/`、`backups/`、`static/`、`data/attachments/` 等目录 |
| 初始化数据库 | 创建 `data/合同台账.db` 及全部业务表（项目合同、资产合同、用户、部门、配置、附件索引、操作日志、字段级变更日志等） |
| Excel 迁移 | 若 `data/合同台账.xlsx` 存在且数据库为首次创建，自动将 Excel 五个工作表（合同台账、用户表、部门列表、系统配置、合同附件）迁移至 SQLite |
| 写入默认数据 | 默认管理员 `admin / 123456`、默认部门“湘潭市机关事务管理局本级-办公室”、默认配置（提醒 60 天、日志保留 90 天） |
| 打开浏览器 | 自动打开 `http://localhost:5000` |

启动成功的标准输出：

```
[INFO] 潭合同 台账管理系统 启动中...
[INFO] 数据库: C:\contract_manager\data\合同台账.db
[INFO] 访问地址: http://localhost:5000
[INFO] 默认管理员: admin / 123456
```

### 3.5 部署验证

1. **环境自检（先做这一步）**：解释器版本应为 **Python 3.8+**（兼容至 3.12）；SQLite 版本应 ≥ **3.25.0**；`import app` 应**无 `SyntaxError`**：
```
python -V                                        # Windows：应 ≥ 3.8
./venv/bin/python -V                             # Linux：应 ≥ 3.8
./venv/bin/python -c "import sqlite3;print(sqlite3.sqlite_version)"   # 应 ≥ 3.25.0
./venv/bin/python -c "import app; print('OK')"   # 模块可导入，无 SyntaxError
```
2. 服务器本机浏览器访问 `http://localhost:5000`，应显示登录页（蓝色渐变背景、LOGO、系统名称）；
3. 使用 `admin / 123456` 登录；
4. 登录后首页应显示五张统计卡片（总合同数、总合同额、已/将到期合同数、待收/支合同数、待收/支总金额），并显示“合同到期提醒”与“待收/支提醒”两个列表区域；
5. 检查“合同台账”页可正常加载列表，“日志审计”页可查询操作日志；
6. 检查登录页与顶栏 LOGO 正常显示。

### 3.6 开放防火墙端口（内网访问必需）

**Windows Server：** 以管理员身份运行命令提示符：

```
netsh advfirewall firewall add rule name="潭合同台账-5000" dir=in action=allow protocol=TCP localport=5000
```

**Linux（firewalld）：**

```
firewall-cmd --permanent --add-port=5000/tcp
firewall-cmd --reload
```

**Linux（ufw）：**

```
ufw allow 5000/tcp
```

然后使用局域网内另一台电脑访问 `http://服务器IP:5000` 验证。

### 3.7 设置开机自启

**Windows（任务计划程序）：**

1. 打开“任务计划程序”→ 创建任务；
2. 常规：名称“潭合同台账管理系统”，勾选“不管用户是否登录都要运行”；
3. 触发器：选择“计算机启动时”；
4. 操作：启动程序，程序为 Python 安装路径（如 `C:\Python310\python.exe`），参数 `app.py`，起始于 `C:\contract_manager`。

**Linux（systemd 服务）：** 创建 `/etc/systemd/system/contract-manager.service`：

```
[Unit]
Description=潭合同台账管理系统
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/contract_manager
ExecStart=/opt/contract_manager/venv/bin/python /opt/contract_manager/app.py
Restart=always
RestartSec=5
User=www-data

[Install]
WantedBy=multi-user.target
```

启用并启动：

```
systemctl daemon-reload
systemctl enable contract-manager
systemctl start contract-manager
systemctl status contract-manager
```

## 四、数据与备份管理

### 4.1 数据文件说明

| 文件/目录 | 内容 | 备份要求 |
|-----------|------|----------|
| `data/合同台账.db` | 全部业务数据（项目合同、资产合同、用户、部门、配置、附件索引、操作日志、字段级变更日志、schema_version 版本记录） | 核心数据，必须备份 |
| `data/attachments/` | 附件文件（项目合同：决策依据、合同、验收结算；资产合同：决策依据、合同） | 与数据库一同备份 |
| `data/合同台账.xlsx` | Excel 工作簿（模板来源、首次迁移数据源） | 数据导入源，建议保留 |
| `data/departments_ddl_backup.sql` | departments 重建前备份脚本（A-02 治理步骤备份） | 随数据一同备份 |
| `backups/` | 系统自动备份的数据库文件（含 A 系列治理快照，见 4.7 节） | 由系统自动管理，保留 30 天 |

### 4.2 自动备份机制

- 系统在**每次写操作**（新增、修改、删除、归档、导入、用户/部门管理、配置修改等）执行前，自动将 `data/合同台账.db` 完整备份为 `backups/合同台账_YYYYMMDD_HHMMSS.db`；
- 备份文件保留 **30 天**，超期自动清理（仅清理 `backups/` 下扩展名为 `.db` 的文件）；
- 备份机制保障任何一次写操作前都有可回滚快照。

### 4.3 手动备份方法

**方法一：直接拷贝（推荐定期执行）**

1. 停止服务（或确认无人在线操作）；
2. 将 `data/` 整个目录拷贝至异地存储（U盘、文件服务器、云盘）：
```
copy /y C:\contract_manager\data C:\backup\data_20260818
```
3. 建议每周备份一次，每月异地归档一次。

**方法二：在线备份（无需停服）**

使用 SQLite 在线备份命令（Linux）：
```
sqlite3 /opt/contract_manager/data/合同台账.db ".backup '/backup/合同台账_20260818.db'"
```

### 4.4 数据恢复方法

**场景一：单条数据误删/误改** —— 从最新备份中取回记录：

1. 定位最近的备份文件（`backups/` 中时间戳最新的 `.db`）；
2. 使用 SQLite 工具（或联系开发人员）从备份中导出该条记录；
3. 将记录写回当前数据库。

**场景二：数据库损坏/丢失，需整体恢复：**

1. 停止服务；
2. 将备份文件拷贝为 `data/合同台账.db`（覆盖损坏文件）；
3. 同时恢复 `data/attachments/` 目录（如有对应备份）；
4. 启动服务并登录验证数据完整性。

### 4.5 从 Excel 台账迁移数据（已停用）

> **V1.5 起该迁移路径已停用**：`data/合同台账.xlsx` 已从系统中删除，全新部署不再依赖 Excel 初始化（首次启动自动建库并写入默认管理员 `admin/123456` 与默认部门）。

- 如确需从历史 Excel 还原：将该文件放置为 `data/合同台账.xlsx`（要求包含“合同台账、用户表、部门列表、系统配置、合同附件”五个工作表，列名与系统一致），**删除或移走 `data/合同台账.db`** 后首次启动，系统自动完成迁移；
- 迁移完成后请核对合同总数、用户数、部门数，并在“日志审计”中确认无异常；
- 日常增量导入请使用系统内置的“导入”功能（导入预览 → 确认导入），无需依赖该文件。

### 4.6 备份恢复操作规程

**备份频率与保留：**

| 备份类型 | 频率 | 保留 | 执行方式 |
|----------|------|------|----------|
| 自动备份 | 每次写操作前 | 30 天 | 系统自动，无需人工干预 |

1. 在演练机（或备用目录）创建独立目录，拷贝最近一次备份的 `.db` 文件与 `attachments/` 附件目录；

**数据库自动迁移（schema_version）：**

- 升级时直接覆盖程序文件（`app.py` 等）并重启即可，无需手工执行建表/加列 SQL；
- `app.py` 启动时 `init_db()` 自动调用 `_run_versioned_migrations()`，按版本号依次执行未应用的迁移（MIGRATIONS 当前 **v1~v32**，含资产合同台账、字段级变更日志、资产租金收缴表、删列/改名/枚举化与统计索引、**短信配置项与 `sms_templates`/`sms_logs` 两表、合同「短信提醒」开关列**、附件表改名、**users 登录与口令策略列**等结构变更），迁移事务包裹，失败自动回滚；其中 **v13/v15/v17/v26/v31** 因需重建被外键引用的表，标记为 `own_transaction`（自行关闭外键并管理事务，提交前执行 `PRAGMA foreign_key_check`）；v19~v25、v27~v30、v32 为纯新增/改名（建表/加列/加配置/删废弃配置），无重建、无需 `own_transaction`；
- 迁移日志以 `[MIGRATE]` 前缀写入 `app.log.err`，可据此确认迁移执行结果；
- 后续新增结构变更由开发向 MIGRATIONS 追加版本号，部署包内不再需要单独 SQL 脚本；
- 如需强制重跑某版本：停止服务后删除 `schema_version` 表中对应版本行，再启动（迁移幂等，可安全重跑）；
- 结构回滚依赖治理快照备份（见 4.7 节），请勿手工修改 `schema_version` 版本号。

### 7.4 重置管理员密码

**当前版本（V1.0）**：停止服务后，在服务器上执行以下 Python 脚本（将“新密码”替换为实际密码）：

```
import hashlib, sqlite3
SALT = "xtsgj_2024_contract"
pw = hashlib.sha256(("新密码" + SALT).encode()).hexdigest()
con = sqlite3.connect(r"C:\contract_manager\data\合同台账.db")
con.execute('UPDATE users SET "密码"=? WHERE "用户名"=?', (pw, "admin"))

## 九、开发与维护编码约束（Python 3.8 兼容）

> 本章面向**后续开发与维护人员**。生产服务器为 **Python 3.8**，而开发机可能使用更高版本（如 3.12）。
> **高版本能跑低版本语法，反之不行**——因此所有代码必须遵守本章约束，保证"开发机写的代码在服务器 3.8 上也能跑"。

### 9.1 为什么需要本章（一次真实事故的教训）

`app.py` 中曾有两处写法仅 **Python 3.12+** 合法：

```python
# ✗ 事故代码（仅 Python 3.12+ 可用）
return [f"{d['\u5355\u4f4d\u540d\u79f0']}-{d['\u79d1\u5ba4\u540d\u79f0']}" for d in get_all_depts()]
```

该写法在 **3.11 及更早版本**上会在**编译源码阶段**报错（不是运行时异常）：

```
SyntaxError: f-string expression part cannot include a backslash
```

表现为：**开发机（3.12）一切正常，部署到服务器（3.8）后 `import app` 直接失败、服务起不来**。
现该处已按 9.3 的写法改正，并在原位置保留了注释说明。

### 9.2 硬性禁止清单

| 禁止 | 说明 |
|---|---|
| ❌ 在 **f-string 表达式内**出现**反斜杠** | 含 `\uXXXX`、`\n`、`\t`、`\"` 等；这是 Python 3.12（PEP 701）才放宽的限制。本项目中文列名以 `\uXXXX` 转义书写，**最容易踩这一条** |
| ❌ 在 **f-string 表达式内**嵌套**同类引号** | 如 `f"{d["键"]}"`（外层与内层同为双引号）；3.12 才允许。外层双引号时，内层必须用单引号 |
| ❌ 使用 **3.9+** 特性 | `str.removeprefix/removesuffix`、`dict1 \| dict2` 字典合并、`list[str]`/`dict[str,int]` 等内建泛型注解（注解会被求值）、`functools.cache`、`zoneinfo`、`graphlib`、`tomllib`、`math.lcm` |
| ❌ 使用 **3.10+ / 3.11+** 特性 | `match/case`、`X \| Y` 联合类型注解、带括号的多上下文管理器（3.10）、`typing.Self`、`ExceptionGroup`/`except*`（3.11） |
| ✅ 允许 | 海象运算符 `:=`（3.8+）、f-string 基本用法、`typing.List[str]` 等 `typing` 泛型、f-string `=` 调试写法（3.8+） |

> 注：**`#` 注释里写 `\uXXXX` 没问题**（注释不参与转义解析）；但**普通字符串/文档字符串里**若要表达"字面的 `\uXXXX`"，必须写成 `\\uXXXX`（双反斜杠），否则会被当成 Unicode 转义而报 `truncated \uXXXX escape`。

### 9.3 正确写法（推荐范式）

**把含转义的取值放到 f-string 外面**，f-string 内只引用变量：

```python
# ✓ 允许：取值语句在 f-string 之外，f-string 内只有变量
def _dept_display(d):
    """返回部门的显示名「单位名称-科室名称」（兼容 Python 3.8 ~ 3.12）。"""
    unit = d["\u5355\u4f4d\u540d\u79f0"]      # 单位名称
    room = d["\u79d1\u5ba4\u540d\u79f0"]      # 科室名称
    return f"{unit}-{room}"                   # 表达式内无反斜杠、无同类引号嵌套
```

等效的两种替代写法（同样兼容 3.8）：

```python
# 备选一：str.format()（参数不属于 f-string 表达式，反斜杠不受限制）
display = "{}-{}".format(d["\u5355\u4f4d\u540d\u79f0"], d["\u79d1\u5ba4\u540d\u79f0"])

# 备选二：字符串拼接
display = d["\u5355\u4f4d\u540d\u79f0"] + "-" + d["\u79d1\u5ba4\u540d\u79f0"]
```

### 9.4 提交前自检（强烈建议纳入日常）

在开发机上装一个 **Python 3.8**（可直接使用服务器同版本，或用官方 embeddable 版），提交前执行：

```bash
python3.8 -m py_compile app.py contract_no.py      # 退出码 0 即通过
python3.8 -m compileall -q .                       # 更彻底：编译整个目录
```

只要这条命令通过，代码就能在服务器上导入运行；**开发仍可用 3.12 进行**（只是不能用 3.12 专有语法）。

**改动前端（`templates/index.html`）时额外必做**：启动服务后执行前端冒烟脚本，确认各视图仍能正常渲染——

```bash
node tools/browser_smoke.mjs --base http://127.0.0.1:5000     # 退出码 0 即通过
```

该脚本用真实浏览器逐个切换左侧 9 个菜单视图并捕捉控制台报错，可拦住"未声明的 `ref`、模板作用域错误、`v-if`/`v-else` 配对错误"导致的**空白页**（V1.8.5 两次真实事故均由此发现）。发版前请一并执行 **5.4 节**的完整检查单。
