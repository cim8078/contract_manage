# A-04 常用查询列建索引（contracts）

> 目标：为 `contracts` 表常用查询列建立索引，提升未来 SQL 化查询与数据量增长后的性能。
> 背景：当前系统为全量内存查询（`read_contracts` 一次性加载），索引不影响现有功能，主要为后续优化与数据增长做准备。

**1. 修改范围**
- 仅修改 `app.py` 的 `init_db()` 迁移逻辑（A-04 块）；不改变任何查询逻辑与接口。
- 全部索引均幂等创建（`IF NOT EXISTS`），重复启动或表重建后重跑不会报错或重复建。

**2. 数据库结构修改（新增 5 个普通索引）**

| 索引名 | 作用列 | 用途 |
|---|---|---|
| `idx_contracts_department` | 所属部门 | 按部门筛选、统计口径 |
| `idx_contracts_procurement_date` | 采购时间 | 时间范围查询、统计 |
| `idx_contracts_next_bid_date` | 下次招采时间 | 到期提醒 |
| `idx_contracts_archived` | 是否归档 | 已归档/未归档过滤 |
| `idx_contracts_handler` | 经办人 | 按经办人查询（过渡索引） |

```sql
CREATE INDEX IF NOT EXISTS idx_contracts_department ON contracts("所属部门");
CREATE INDEX IF NOT EXISTS idx_contracts_procurement_date ON contracts("采购时间");
CREATE INDEX IF NOT EXISTS idx_contracts_next_bid_date ON contracts("下次招采时间");
CREATE INDEX IF NOT EXISTS idx_contracts_archived ON contracts("是否归档");
CREATE INDEX IF NOT EXISTS idx_contracts_handler ON contracts("经办人");
```

- 命名规则：`idx_contracts_<列名英文/拼音>`，避免中文列名直接入索引名。
- “编号”唯一索引不重复创建：A-01 的 `idx_contracts_no`（unique=1）直接复用。
- 实测当前库共 6 个索引：上述 5 个普通索引（`unique=0`、origin=`c`）+ `idx_contracts_no`。

**3. 数据库记录修改（0 条）**
- 索引是纯结构对象，不触碰任何数据；639 条合同记录原样不动。

**4. 解决的问题**
- 背景：当前系统是“全量内存查询”（`read_contracts` 一次性加载），索引不改变现有功能与查询路径，主要为**后续 SQL 化查询与数据量增长**做准备。
- 目标列均为高频查询/统计/提醒场景：部门（筛选、卡片口径）、采购时间与下次招采时间（到期提醒、时间范围）、是否归档（已归档/未归档过滤）、经办人（按经办人查询）。
- 数据量增大后，这些列的 `WHERE`/`GROUP BY`/`ORDER BY` 可直接走索引扫描，避免全表扫。
- 行为不变：现有列表/搜索/统计/提醒/待支付接口回归正常，响应时间无退化（实测通过）。

**5. 过渡索引说明**
- `经办人` 为多值列（同一合同可有多人，用顿号/斜杠分隔），索引价值有限；本项按任务要求先建为过渡索引，代码注释已注明：**档位 B 拆分多值列后将废弃本索引**。

**6. 验收结果（已实测）**
1. `PRAGMA index_list(contracts)` 显示全部目标索引且无重复。
2. 现有列表/搜索/统计/提醒/待支付接口回归正常，响应时间无退化。

**7. 回滚方式**
```sql
DROP INDEX IF EXISTS idx_contracts_department;
DROP INDEX IF EXISTS idx_contracts_procurement_date;
DROP INDEX IF EXISTS idx_contracts_next_bid_date;
DROP INDEX IF EXISTS idx_contracts_archived;
DROP INDEX IF EXISTS idx_contracts_handler;
```
- 逐个 DROP 即可，无数据影响；A-01 的 `idx_contracts_no` 不属于本项，保留不动。
