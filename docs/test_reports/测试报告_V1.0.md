## 一、测试概述

### 1.1 测试目的

针对系统近期最易出问题的三块核心逻辑做脚本化验证，确认其行为与设计文档一致：

1. **版本化迁移幂等性**——删除 `schema_version` 中的版本行后重启迁移，验证重建表类迁移（v13/v15/v17）可安全重放、不破坏数据与外键；
2. **数据权限边界**——验证不同角色（管理员/普通用户/查询用户）在项目合同与资产合同上的可见范围、写权限、归档责任人限制、删除防误删是否正确；
3. **资产租金收缴**——验证 `asset_rent_collections` 子表「整表替换」语义、防误删确认、归档后只读、字段级变更日志是否按预期落库。

- 迁移测试与租金收缴测试为**写操作**，均将生产库复制到临时目录后对副本执行，**生产数据零改动**；租金测试重定向 `DB_PATH` 并直接调用真实路由函数（`api_create_asset`/`api_save_asset_rent`/`api_archive_asset`）获取真实 HTTP 状态码。
- 权限测试通过 HTTP 调用本地 Flask，但所有写操作用例均命中「拒绝」分支（403/409），在写库前返回；登录会追加审计日志（append-only，属正常业务行为）。

## 四、性能结论

**说明：本轮未执行性能/压力测试，以下为代码走读结论，非实测数据。**

| 观察点 | 现状 | 判断 |
|---|---|---|
| 只读缓存 | `read_contracts`/`read_assets` 使用进程内 TTL 2s 缓存 + 写后失效 | 首页多接口并发读取只查一次库，设计合理 |
| 每次写前全量备份 | `db_exec`/`app_row` 等每次写操作调用 `_backup()`，整库（约 1.15MB）复制到 `backups/` | 单次开销可控，但**写密集/批量导入场景下 I/O 与磁盘占用会放大**，属待评估项 |
| 统计/提醒索引 | v18 新增 4 个索引；文档注明当前数据量下优化器基本不会选中 | 面向数据增长预置，当前无负面影响 |
| 登录审计 | 每次登录写审计日志并可能触发备份 | 对并发登录场景有一定写放大，待评估 |

**结论**：当前数据规模（639/5/16）下单机性能无可见瓶颈；但「每次写前全量备份」在批量导入、高频写场景下的开销**未经压测**，上线前建议补一次写入量与备份磁盘占用评估。

## 五、安全结论

**实测通过（权限边界）：**

- 数据权限按「角色 + 部门/分管部门」双重过滤，列表/详情/可见范围口径一致；
- 越权编辑返回 403（「只能编辑本部门或分管部门合同」）；
- 资产归档仅管理员或该合同责任人可执行（非责任人 403）；
- 有租金记录的资产删除需显式 `delete_rent` 确认，否则 409（数据库 `ON DELETE RESTRICT` 兜底）。

**文档已列明、本轮未重新测试的安全缺口（引自《系统开发文档》§6、《系统功能提升实施方案》）：**

| 缺口 | 现状 | 计划 |
|---|---|---|
| 密码存储 | SHA256(密码+固定盐) | 升级 PBKDF2（P1） |
| 会话密钥 | 源码内置固定值 | 环境变量化（P1） |
| 登录防护 | 无失败锁定 | 增加锁定（P1） |
| 敏感操作留痕 | 部分 | 增强（P0） |

## 六、遗留风险

1. **安全加固未完成**：密码哈希、会话密钥、登录锁定三项 P1 计划未落地，公网/多用户环境存在风险。
2. **性能未压测**：尤其「每次写前全量备份」在批量导入/高频写下的开销未量化。
3. **数据质量待业务确认**：金额文本 245 条待确认、枚举「部分结算」待确认、「是否有签证或变更」全库为空待回填（引自《数据字典表》）。
4. **无自动化测试框架**：本次为脚本化功能测试，未纳入 CI/日常回归，回归依赖手工运行。
5. **观察项 1**：`updated` 统计口径与「值变化条数」不一致，属轻微语义问题。

---

## 七、是否可上线建议

**结论：就本次覆盖的三块核心逻辑而言，可上线（无阻断性缺陷）。** 但建议满足以下条件后再正式发布：

1. **必须项（上线前）**
   - 完成至少 P1 安全加固（密码 PBKDF2、会话密钥环境变量化、登录失败锁定）；
   - 补一次批量导入/高频写场景的性能与备份磁盘占用评估。

2. **建议项（可并行或上线后尽快）**
   - 数据质量项由业务确认收口（金额 245 条、枚举「部分结算」、签证变更列回填）；
   - 将 `test_migrations.py` / `test_permissions.py` / `test_rent_collections.py` 纳入日常回归或 CI。

3. **低风险可延后**
   - `replace_asset_rent` 的 `updated` 统计口径优化（观察项 1）。
