## 1. 文档与代码摘要

### 1.1 《系统开发文档》要点

- **技术栈**：Flask + SQLite（单文件库）+ Vue 3 + Bootstrap 5（前端单文件 `templates/index.html`，依赖全部本地化，无外网请求）；依赖仅 `flask / openpyxl / filelock`。
- **架构**：请求 → Flask 路由（`login_required` / `admin_required` + `_visible_depts/_scope_contracts/_scope_assets` 数据权限）→ `sqlite3` → 只读 TTL 2s 缓存 → 审计日志。
- **数据模型**：13 张业务表（settings、users、departments、project_contracts、project_attachments、asset_contracts、asset_attachments、asset_rent_collections、field_change_logs、operation_logs、sms_templates、sms_logs、schema_version）。
- **迁移机制**：`MIGRATIONS` 版本化迁移 v1~v30，启动时 `init_db()` 自动补齐；v13/v15/v17/v26 等重建表类迁移以 `{"own_transaction": True}` 自行管理事务（先关外键再重建）；迁移函数须幂等，删除版本行可强制重放。
- **权限模型**：角色 = 管理员 / 普通用户 / 查询用户；数据范围 = 本部门 ∪ 分管部门；**项目合同按「所属部门」、资产合同按「管理部门」**过滤；查询用户只读。
- **业务能力**：项目/资产合同 CRUD 与归档、租金收缴明细（整表替换）、首页卡片、到期提醒、待收/支提醒、查询统计、附件、导入导出、打印 PDF、操作日志与字段级变更日志、短信提醒（V1.5+）。
- **安全现状（文档自述缺口）**：密码 SHA256(密码+固定盐)、会话密钥源码内置、无登录失败锁定、短信 AK/SK 明文存库。

### 1.2 《数据字典表》要点

- 项目合同主表 29 列；资产合同 `asset_contracts`、租金明细 `asset_rent_collections`、字段级日志 `field_change_logs`、短信模板/流水表字段字典齐全。
- 数据质量规则 Q1~Q17：编号唯一、枚举受控、日期 yyyy-mm-dd、金额数字与非负、所属部门存在、资产合同三项必填、字段修改留痕等。
- 待业务确认项：金额文本 245 条待回填、「部分结算」枚举待定、「是否有签证或变更」待回填、标签体系未落地。

## 3. 测试策略

### 3.1 隔离与安全（红线：不触碰生产库）

1. **绝不直接读写 `data/合同台账.db`**。仅以其为只读源，复制到 `test_data/` 下的测试库。
2. **运行时隔离**：把 `app.py`、`contract_no.py`、`templates/`、`static/` 复制到 `test_data/runtime/`，并让该副本的 `data/` 指向测试库副本；由副本启动 Flask（`app.py` 在导入时执行 `init_db()`，因此副本是唯一安全形态）。
3. 每次测试开始前从 `backups/` 中**只读**复制一份最新完整库作为「迁移基线库」，避免反复使用已迁移过的库。
4. 所有写操作只发生在 `test_data/`；测试结束核对生产库 `mtime`/行数未变。

### 3.2 目录与产物

```
test_data/                     # 已 .gitignore；测试库与运行时副本
  base_合同台账.db              # 每次从 backups/ 复制的迁移基线
  work_*.db                    # 各模块工作库
  runtime/                     # app.py 等只读副本 + 独立 data/
tests/
  conftest_lite.py             # 公共：临时库构建、服务启动/停止、登录、SQL 断言
  test_m01_migrations.py
  ...（M01~M15，每模块一个脚本）
  run_all.py                   # 顺序执行、汇总
docs/test_reports/
  测试计划与用例表_V2.0.md      # 本文档
  Mxx_*.md                     # 各模块执行结果与问题清单
  测试报告_V2.0.md              # 最终汇总报告
```

### 3.3 脚本技术方案

- **语言/库**：Python 3.14.6 + `requests` 2.34.2（真实 HTTP）+ `sqlite3`（库内断言）+ `openpyxl`（导入导出比对）。
- **服务**：测试副本以 `python app.py` 启动在独立端口（默认 **5099**），脚本内 `POST /api/login` 取得会话 Cookie 后操作。
- **迁移类用例**：不走 HTTP，直接对测试库副本执行 `_run_versioned_migrations` 语义（复制→删版本行→导入 app → 断言），并在断言前执行 `PRAGMA foreign_key_check`。
- **断言口径**：HTTP 状态码 + 响应 JSON 关键字段 + 库内行/字段值 + 审计日志（operation_logs / field_change_logs）。
- **数据对照**：期望值优先由同库 SQL 计算（如可见范围 = `SELECT ... WHERE 所属部门 IN (...)`），避免硬编码易漂数字；关键卡点数字硬编码并注明基线。

### 3.4 执行顺序

M01 → M02 → M03 → M04 → M05 → M06 → M07 → M08 → M09 → M10 → M11 → M12 → M13 → M14 → M15。
每个模块：先出「用例表」→ 生成脚本 → 执行 → 输出该模块执行结果与问题清单 →（用户确认）→ 下一模块。
