## 一、评审说明

本次评审立足合同管理科日常管理需要，对照《合同台账管理系统需求规格说明书（V3.1）》，结合系统当前实际功能逐项核对，并提出增减与调整建议。评审范围覆盖系统全部功能模块：登录认证、合同台账、查询统计、到期提醒、用户与部门管理、日志审计、系统设置。

> 总体结论：系统核心需求已全部实现，且超出原始需求完成了附件管理、Excel 导入、合同归档、分管部门授权、日志审计、数据字典、操作手册等扩展功能，可满足合同台账管理的基本要求；主要差距集中在合同全生命周期管理、财务勾稽校验、提醒主动触达与安全加固方面，建议按本报告优先级逐步完善。

## 二、总体评价

- 核心业务闭环完整：合同从新增、查询、统计、导出、归档到提醒的全流程可用，界面蓝色科技风格统一，操作体验良好。
- 权限模型合理：管理员全量可见，普通用户与查询用户按“本部门加分管部门”统一过滤列表、提醒、统计与导出，口径一致。
- 数据基础扎实：数据字典、用户操作手册、第三方许可清单已配套，具备交付与审计条件。
- 存在的差距：缺少合同状态管理、财务金额勾稽校验、删除复核留痕与主动提醒触达；安全方面密码存储与登录防护可进一步加固。

## 四、建议新增功能

### （一）高优先级：直接影响业务合规与风险防控

- **增加“合同状态”字段**：建议状态为拟签、执行中、已完工、已结算、已终止、已归档，替代当前分散的“是否结算加归档状态”标志，由状态驱动统计口径与编辑权限，避免口径混乱。
- **增加财务勾稽校验**：未支付金额自动按“结算金额减已支付”计算或提交校验；合同金额必须大于 0；日期逻辑校验（完工时间不得早于开工时间、下次招采时间应晚于当前日期），防止手工数据矛盾。
- **删除与修改复核留痕**：删除、归档、清空下次招采时间等敏感操作除二次确认外，强制填写操作原因并记录到日志，满足经办与审批分离的机关管理要求。
- **提醒主动触达**：当前提醒仅登录时实时计算，用户不上线即无法感知。建议首页增加“逾期未处理合同”列表，提醒支持“推迟 7/15/30 天”，远期可对接短信或邮件通知。

### （二）中优先级：提升管理效率

- **统计维度增强**：增加未支付金额汇总（欠款风险监控）、招标控制价与合同金额预算执行对比、按采购方式统计三个口径。
- **编号规则化**：支持“年度加类别”自动编号（如 2026-FW-001），新增页面提供编号格式提示，降低手工编号错误。
- **附件管理补全**：补充附件大小限制与格式白名单，附件目录纳入备份与恢复范围，附件操作留痕（当前已有日志埋点）。
- **台账批量操作**：批量修改下次招采时间、批量归档，提升延续性项目维护效率。

### （三）低优先级：可选增强

- 批量导入增加错误报告与逐条校验结果预览，导入前可下载标准模板。
- 首页增加“本月待办”“逾期未处理”小型卡片，方便领导快速掌握动态。

## 五、建议调整（安全与合规）

| 调整项 | 现状 | 建议 |
| --- | --- | --- |
| 密码存储 | SHA256 固定盐 | 改用 PBKDF2 或 scrypt（如 werkzeug 安全模块），历史密码登录时自动迁移 |
| 登录防护 | 无失败限制 | 连续失败锁定或验证码，部署 HTTPS |
| 会话密钥 | 内置固定值 | 改为环境变量配置，避免源码泄露 |
| 日志防篡改 | 可追加可修改 | 操作日志只追加、禁止修改，导出动作自身留痕 |
| 备份恢复 | 备份至 backups 目录 | 补充《备份恢复操作规程》，配置定时备份并定期恢复演练 |

## 六、可简化或删除项

- “查询用户”角色保留作只读账号，无需删除。
- “决策依据、招标控制价决策的依据”等低使用率字段建议保留文本输入，不做下拉约束，避免破坏存量数据。
- 日志“查询不记录”符合大数据量实际，保持现状。
- 合同浏览页已提供“打印为PDF”（新标签页打印视图 + 打印人/打印时间水印），可满足审计留档需要；打印操作本身以浏览器打印日志为准，系统暂不强制记录，后续如需可增加打印留痕。
