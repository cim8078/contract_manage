## 1. 文档说明

### 1.1 目的
- 统一全系统字段、枚举、主数据的定义与取值标准，作为数据治理、清洗、打标和系统改造的依据。
- 消除当前数据中“同义不同写、全角半角混用、枚举自由填写、双存储漂移”等问题。

### 1.2 数据源现状（治理后）
| 项 | 现状 | 建议 |
|---|---|---|
| 运行存储 | SQLite（`data/合同台账.db`）为系统实际读写库，已应用 schema 版本 **v28**（A-07 版本化迁移，v1~v28） | 确定为唯一权威数据源 |
| 交付存储 | Excel（`data/合同台账.xlsx`）用于导入/导出、人工查阅（项目合同模板/导入为 29 列；资产合同模板/导入为 29 个字段，见第 10 节） | 仅作导出交付物，禁止直接修改后回灌 |
| 资产合同来源 | 源表《资产合同台账.xlsx》（湘潭市国有资产租金缴纳情况明细表，2026 年度 `Sheet3`），已导入 `asset_contracts` 5 条 | 后续年度数据按同格式导入，勿手工改库 |
| 备份 | `backups/` 自动备份，保留 30 天 | A-01~A-08 治理已完成，后续再治理前追加快照备份 |
| 双库一致性 | 历史上 Excel 与 SQLite 多次不一致（如部门字段） | A-03 已修复 71 条缺科室后缀部门数据，每次治理后校验两库差异并出具报告 |
| 治理状态 | 枚举已标准化（A-08）、部门已修复（A-03）、日期已规范化（A-05/A-06）；2026-09 新增资产合同台账与日志扩展 | 金额文本 245 条仍待业务确认（见 A-05/A-06 清单）；资产合同 5 条中 id1~3 已填“下次出租时间” |

### 1.3 角色与权限（引用）
| 角色 | 权限 |
|---|---|
| 管理员 | 维护用户/部门/系统配置；操作全部项目合同与资产合同（含归档、附件、导入导出）；打标治理 |
| 普通用户 | 项目合同：新增，编辑/删除本部门（含分管部门）合同；资产合同：新增/编辑/删除（不受部门限制），归档限本人为责任人时；设置本人负责合同提醒 |

**关键口径**

- 租期年数 = 整年数（按起止日计算），不足一年按 0 计；总合同额 = 年租金（元）× 租期年数。
- **“已缴租金合计”不是本表列**：由资产租金收缴表按合同汇总 `实缴金额（元）` 得到（计算列 `paid_total`，见第 14 节）；资产列表“已缴租金合计(元)”列、查询统计与首页图表均采用此口径；另有计算列 `due_total`（应缴合计）与 `rent_count`（收款记录数）。
- 租金应收差额 = 该合同下 `Σ应缴金额（元） − Σ实缴金额（元）`（按合同汇总，汇总可为负）；“待收合同数”取差额 > 0 的合同数。

- 部门可见范围按“管理部门”精确匹配，与项目合同按“所属部门”匹配的规则对称。

## 16. 短信发送流水表字段字典（sms_logs，v22 新增）

> 用途：记录每一次短信下发（含定时提醒、催办、点对点、失败重发），并保存平台回执与对方回复；是“短信记录”页面的数据来源。
> 当前数据量：随发送产生（截至 V1.5 文档更新时为测试数据）。

| 列（数据库） | 数据类型 | 必填 | 取值/格式 | 业务说明 |
|---|---|---|---|---|
| id | INTEGER | 是 | 自增主键 | 流水号；同时作为发往平台的 `guId`（`SMS{id}`），用于回执/回复对账 |
| 时间 | TEXT | 否 | YYYY-MM-DD HH:MM:SS | 发送时间 |
| 场景 | TEXT | 否 | expire / receivable / payable / urge / manual | 对应模板场景 |
| 关联类型 | TEXT | 否 | project / asset / 手动 | 关联对象类型；无合同上下文的点对点为“手动” |
| 关联ID | TEXT | 否 | 合同 id | 项目合同 id 或资产合同 id |
| 关联编号 | TEXT | 否 | — | 项目合同编号；资产合同取“位置”或 id |
| 关联名称 | TEXT | 否 | — | 项目名称 / 资产名称 |
| 接收人类型 | TEXT | 否 | 经办人/现场负责人/责任人/承租人/手动 | 收件人角色 |
| 接收人 | TEXT | 否 | 姓名/单位 | 收件人名称 |
| 手机号 | TEXT | 否 | 11 位手机号 | 实际下发号码（已规范化，按号码去重） |
| 短信内容 | TEXT | 否 | — | 实际下发内容（含签名） |
| 去重键 | TEXT | 否 | `场景\|关联类型\|关联ID\|手机号\|ISO年-周` | 定时提醒的周去重键；**部分唯一索引**保证同一提醒同一周同一手机号仅一条。手动催办/点对点/重发为空 |
| 触发方式 | TEXT | 否 | 定时 / 催办 / 点对点 / 重发 | 发送来源 |
| 发送人 | TEXT | 否 | 用户名 / 系统 | 定时任务为“系统”；手动发送为操作人用户名 |
| 状态 | TEXT | 否 | 待发送 / 成功 / 失败 | 发送结果 |
| 外部guId | TEXT | 否 | `SMS{id}` | 提交给平台的消息 id |
| 回执状态码 | TEXT | 否 | 平台回执码 | 由平台回执回调写入 |
| 回执描述 | TEXT | 否 | 平台回执描述（如 DELIVRD） | 由平台回执回调写入 |
| 回复时间 | TEXT | 否 | — | 对方回复时间，由回复回调写入 |
| 回复内容 | TEXT | 否 | — | 对方回复内容，由回复回调写入 |
| 错误信息 | TEXT | 否 | 中文可操作提示 + 原始错误 | 发送失败原因（网络不通、未配置密钥等） |
| 请求时间戳 | INTEGER | 否 | 毫秒时间戳 | 发往平台的签名用 timestamp |

**索引（6 个）**：`idx_sms_logs_time`（时间）、`idx_sms_logs_object`（关联类型+关联ID）、`idx_sms_logs_phone`（手机号）、`idx_sms_logs_status`（状态）、`idx_sms_logs_guid`（外部guId）、`idx_sms_logs_dedup`（去重键，**部分唯一索引**：`WHERE 去重键 IS NOT NULL AND 去重键 <> ''`）。

**关键口径**

- 每次发送**一行**；失败重发不覆盖原记录，而是新增一条 `触发方式=重发` 的流水，便于追溯。
- 「每人一条」= 去重键包含手机号，同一提醒的多个收件人各自一行、互不覆盖。
- 表结构不参与导出/导入模板；由系统在发送过程中写入。
- **内容合规（平台注意事项）**：`短信内容` 中**不出现「【】」**（否则判多签名阻断，签名由平台按应用签名自动添加）；内容经敏感词校验；超长按「单段字数」拆分为多行；号码仅接受有效 11 位手机号；同一号码每日成功条数受 `sms_daily_per_phone` 限制、两次发送间隔受 `sms_min_interval_sec` 限制；被拦截的号码不写流水，仅在接口结果中返回原因。
