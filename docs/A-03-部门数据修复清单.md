# A-03 部门数据修复清单（缺科室后缀 → 建议科室）

修复依据完全来自 `app.py` `init_db()` 中的自动规则（`_DEPT_RULES`），具体如下：

**1. 判定“缺科室后缀”的条件**
- 逐条扫描 639 条合同的 `所属部门`：
  - 不含 `-`（即只有单位、没有科室），如“湘潭市机关事务管理局后勤中心”；
  - 或含 `-` 但拆分后的 `(单位名称, 科室名称)` 不在 `departments` 表的 13 个合法组合里。
- 实测共 71 条，全部是第一种情况（只有单位“湘潭市机关事务管理局后勤中心”、无科室）。

**2. 修复规则（按顺序命中即止，取项目名称做关键字匹配）**

| 优先级 | 命中的关键字（项目名称含其一） | 建议科室 |

| R1 | 公车、车辆、平台委托、平台服务、新能源 | 公车管理组 |

- 市民之家专班 1 条（246610 市民之家地下停车场指示牌改装）
- 周转住房专班 1 条（256703 周转房 602 空调采购）

**4. “供业务复核”的含义**
- 该规则是**自动化建议**，未与业务逐条确认；完整对应关系（编号 → 项目名称 → 原值 → 修复值 → 命中关键字）已写入 `docs/A-03-部门数据修复清单.md`。
- 若业务认为某条科室归属不对，直接按清单修改该合同的 `所属部门` 即可（因外键已生效，修改后的值必须是 departments 表中的合法组合）。
- 若需整体调整规则，改 `_DEPT_RULES` 后重跑迁移即可（重建前备份在 `backups/合同台账_A03_重建前_20260823_152834.db`）。
