# 合同编号规则（6 位）与自动生成说明

> 2026-10 统一名称后版本：科室（中心）序号扩展为 1~9（新增 `9=政策法规科`），
> 名称统一为简称（如“国有资产科”“财务科”“后勤中心”“资产中心”“公车中心”）。
> 已与 `departments` 部门表逐条核对，详见文末“部门表名称一致性核对结果”。

## 一、编号格式

合同编号为 6 位数字字符串：`第 1-2 位年度 + 第 3 位科室（中心）序号 + 第 4 位中心组室序号 + 第 5-6 位顺序号`
（顺序号不足两位时左侧补 `0`）。示例：`266401` = 2026 年 + 市机关后勤服务中心(6) + 物业组(4) + 第 01 号。

## 二、年度编码（第 1-2 位）

年度后两位。例如 2026 年记为 `26`（2007 年记为 `07`，编号仍以字符串保存，前导零不丢失）。

## 三、科室（中心）序号（第 3 位，统一后名称）

| 第 3 位 | 科室（中心） |
|---|---|
| 1 | 办公室 |
| 2 | 国有资产科 |
| 3 | 公共事务科 |
| 4 | 人事科 |
| 5 | 财务科 |
| 6 | 后勤中心 |
| 7 | 资产中心 |
| 8 | 公车中心 |
| 9 | 政策法规科 |

说明：原“国有资产管理科、公共事务管理科、人事与政策法规科、财务管理科、市机关后勤服务中心、
市行政事业单位国有资产事务中心（市国资中心）、市公车中心”等名称一律按上表统一后名称执行；
其中“人事与政策法规科”拆分为“人事科”(4) 与“政策法规科”(9)。

## 四、中心组室序号（第 4 位）

| 第 3 位 | 中心组室（第 4 位取值） |
|---|---|
| 1、2、3、4、5、9（局本级科室） | 第 4 位统一为 `1` |
| 6（后勤中心） | 1=综合组，2=公车组，3=工程组，4=物业组，5=后勤组，6=市民之家专班，7=周转住房专班 |
| 7（资产中心） | 1=综合组，2=房地资产组，3=通用资产组，4=集采组 |
| 8（公车中心） | 1=现场负责组 |

其他未列明的中心或内部组室**不得自动生成、不得猜测编号**，须先补充规则。

## 五、顺序号（第 5-6 位）

同一“年度 + 科室（中心）+ 中心组室”前缀下，第 5-6 位从 `01` 开始连续递增；
新增合同时查询对应表同一前缀下的最大顺序号并 **加 1**；该前缀下暂无记录时从 `01` 开始；
当前规则下顺序号范围为 `01`~`99`，超过 `99` 需另行扩展编号规则（此时接口返回“需扩展编号规则”错误，不会生成错误编号）。

## 六、数据库映射

| 对象 | 写入字段 | 说明 |
|---|---|---|
| 项目合同 | `project_contracts."编号"` | 已有数据保持原编号不变，不重编、不修改 |
| 资产合同 | `asset_contracts.id` | v26 起 id 由自增整数改为 6 位编号（TEXT）；历史 id 原值保留 |

项目合同与资产合同各自独立递增，同一表内编号唯一（`project_contracts."编号"` 唯一索引、`asset_contracts.id` 主键）。
编号以 6 位字符串保存，前导零不丢失。

## 七、实现位置

| 位置 | 说明 |
|---|---|
| `contract_no.py` | 编号规则本体：科室（中心）/中心组室编号表、单位与科室别名归一键、前缀解析、顺序号计算 |
| `app.py` → `next_contract_number()` | 读取目标表既有编号并计算下一个编号 |
| `POST /api/contracts` | 新增项目合同：请求未带编号时自动生成并写入 `编号` |
| `POST /api/asset_contracts` | 新增资产合同：请求未带编号时自动生成并写入 `id` |
| `GET /api/contract_number/next` | 编号预览（不写库），供新增页面即时展示 |
| `v26` 迁移 | `asset_contracts.id` 由 `INTEGER AUTOINCREMENT` 重建为 `TEXT PRIMARY KEY`，历史数据原值搬运 |
| `v27` 迁移 | 删除部门表历史残留行「本级-人事与政策法规科」（被引用时跳过并告警） |

### 名称口径说明

- **单位名称**：部门表登记为“湘潭市机关事务管理局XX”（如 `湘潭市机关事务管理局后勤中心`），
  规则中的中心名称使用简称（`后勤中心`/`资产中心`/`公车中心`/`局本级`），
  `contract_no.py` 的 `UNIT_ALIASES` 仅做该单位前缀归一。
- **科室/组室名称**：一律以统一后名称为准，**不做旧名自动归一**。
  历史写法（如“物业管理组/工程建设组/公车管理组/后勤管理组/人事与政策法规科/国有资产管理科/资产科”等）
  统一按“未配置编号规则”处理，并在错误提示中说明对应新名称，由业务确认后使用新名称。

## 九、历史数据

历史编号一律不修改、不重编、不回填（含历史上 8~9 位等非 6 位编号）。
因名称统一导致的历史前缀与新规则前缀不一致时，仅对新增数据按新规则处理。
